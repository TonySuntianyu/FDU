# Lab3 快递物流管理系统 - 领域模型

## 1. 领域模型概述

本领域模型用于支持快递物流公司的包裹全生命周期跟踪管理，主要涵盖揽收分拣和运输配送两个核心业务环节。

## 2. 核心实体

### 2.1 包裹相关实体

#### 包裹（Package）
- **属性**：
  - 包裹编号（packageId）：唯一标识
  - 运单号（waybillNumber）：运单编号
  - 当前状态（currentStatus）：包裹当前状态（揽收、分拣、运输中、已到达等）
  - 当前位置（currentLocation）：当前所在位置（网点/中转站）
  - 下一站（nextStation）：下一个目的地
  - 预计到达时间（estimatedArrivalTime）：预计到达下一站的时间
  - 重量（weight）：包裹重量
  - 尺寸（dimensions）：包裹尺寸
  - 收件人地址（recipientAddress）：收件人地址
  - 收件人联系方式（recipientContact）：收件人联系方式
  - 发件人信息（senderInfo）：发件人信息
  - 创建时间（createTime）：包裹创建时间
  - 异常状态（isAbnormal）：是否处于异常状态
  - 异常原因（abnormalReason）：异常原因描述

- **关系**：
  - 关联一个运单（Waybill）
  - 关联多个包裹轨迹记录（PackageTrack）
  - 关联多个路径规划历史（RoutePlanHistory）
  - 关联多个运输任务（TransportTask）
  - 关联多个分拣任务（SortingTask）

#### 运单（Waybill）
- **属性**：
  - 运单号（waybillNumber）：唯一标识
  - 创建时间（createTime）：运单创建时间
  - 创建网点（originServicePoint）：寄件网点
  - 目的网点（destinationServicePoint）：收件网点

- **关系**：
  - 关联一个包裹（Package）

### 2.2 站点相关实体

#### 网点（ServicePoint）
- **属性**：
  - 网点编号（servicePointId）：唯一标识
  - 网点名称（name）：网点名称
  - 地址（address）：网点地址
  - 类型（type）：网点类型（寄件网点、收件网点）

- **关系**：
  - 关联多个包裹（作为寄件网点或收件网点）
  - 关联多个分拣任务（作为分拣地点）

#### 中转站（TransferStation）
- **属性**：
  - 中转站编号（stationId）：唯一标识
  - 中转站名称（name）：中转站名称
  - 地址（address）：中转站地址

- **关系**：
  - 关联多个分拣任务（SortingTask）
  - 关联多个运输任务（作为起点或终点）

### 2.3 运输相关实体

#### 车辆（Vehicle）
- **属性**：
  - 车辆编号（vehicleId）：唯一标识
  - 车牌号（licensePlate）：车牌号
  - 容量（capacity）：车辆容量
  - 当前位置（currentLocation）：车辆当前位置
  - 下一站（nextStation）：车辆下一站
  - 预计到达时间（estimatedArrivalTime）：预计到达下一站的时间
  - 当前状态（currentStatus）：车辆状态（空闲、运输中、维护中等）

- **关系**：
  - 关联一个司机（Driver）
  - 关联多个运输任务（TransportTask）

#### 司机（Driver）
- **属性**：
  - 司机编号（driverId）：唯一标识
  - 姓名（name）：司机姓名
  - 联系方式（contact）：联系方式

- **关系**：
  - 关联多个车辆（Vehicle）

#### 运输任务（TransportTask）
- **属性**：
  - 任务编号（taskId）：唯一标识
  - 起点（origin）：起点位置
  - 终点（destination）：终点位置
  - 创建时间（createTime）：任务创建时间
  - 状态（status）：任务状态（待分配、运输中、已完成）
  - 实际出发时间（actualDepartureTime）：实际出发时间
  - 实际到达时间（actualArrivalTime）：实际到达时间

- **关系**：
  - 关联一个车辆（Vehicle）
  - 关联多个包裹（Package）
  - 关联一个路径规划（RoutePlan）

### 2.4 路径规划相关实体

#### 路径规划（RoutePlan）
- **属性**：
  - 规划编号（planId）：唯一标识
  - 起点（origin）：起点
  - 终点（destination）：终点
  - 规划路径（plannedRoute）：规划的路径（站点序列）
  - 预计总时间（estimatedTotalTime）：预计总运输时间
  - 创建时间（createTime）：规划创建时间
  - 是否当前有效（isCurrent）：是否为当前有效规划

- **关系**：
  - 关联一个包裹（Package）
  - 关联多个路径规划历史记录（RoutePlanHistory）
  - 关联多个运输任务（TransportTask）

#### 路径规划历史（RoutePlanHistory）
- **属性**：
  - 历史记录编号（historyId）：唯一标识
  - 原路径规划（originalPlan）：原路径规划
  - 新路径规划（newPlan）：新路径规划
  - 变更原因（changeReason）：变更原因（天气变化、交通管制、路况异常等）
  - 变更时间（changeTime）：变更时间
  - 变更位置（changeLocation）：变更发生的位置（中转站）

- **关系**：
  - 关联一个包裹（Package）
  - 关联原路径规划（RoutePlan）
  - 关联新路径规划（RoutePlan）

### 2.5 分拣相关实体

#### 分拣任务（SortingTask）
- **属性**：
  - 任务编号（taskId）：唯一标识
  - 分拣地点（sortingLocation）：分拣地点（网点或中转站）
  - 创建时间（createTime）：任务创建时间
  - 完成时间（completionTime）：完成时间
  - 状态（status）：任务状态（待处理、处理中、已完成、异常）

- **关系**：
  - 关联多个包裹（Package）
  - 关联一个网点或中转站（ServicePoint/TransferStation）

### 2.6 轨迹相关实体

#### 包裹轨迹（PackageTrack）
- **属性**：
  - 轨迹编号（trackId）：唯一标识
  - 位置（location）：位置信息
  - 状态（status）：包裹在该位置的状态
  - 时间（timestamp）：时间戳
  - 操作类型（operationType）：操作类型（揽收、分拣、装车、卸车、到达等）

- **关系**：
  - 关联一个包裹（Package）

## 4. 关键业务规则

1. **包裹状态流转**：
   - 揽收 → 分拣 → 运输中 → 中转站分拣 → 运输中 → ... → 到达目的网点

2. **路径规划规则**：
   - 包裹在起点会规划好全程路线
   - 路径规划可以变更，但需要记录变更历史
   - 路径变更通常发生在中转站

3. **分拣规则**：
   - 根据路径规划中的下一站进行分拣
   - 分拣异常需要标记包裹为异常状态

4. **运输任务分配规则**：
   - 根据车辆容量、路线规划、当前位置等因素分配

5. **轨迹记录规则**：
   - 包裹的每个状态变化都需要记录轨迹

## 5. 领域模型对系统目标的支持程度分析

### 系统目标
实现包裹全生命周期的跟踪管理，提供包裹、车辆、中转站的基本查询能力。

### 场景验证

#### 场景一：查询包裹当前状态（当前位置、下一站）

**需求**：客户输入运单号，系统显示包裹当前状态、当前位置、下一站、预计到达时间。

**模型支持**：
- ✅ **完全支持**
- 包裹实体直接包含 `currentStatus`（当前状态）、`currentLocation`（当前位置）、`nextStation`（下一站）、`estimatedArrivalTime`（预计到达时间）属性
- 通过运单号查询包裹实体即可获取所有需要的信息
- 包裹轨迹实体记录完整的历史轨迹，可按时间排序查询

**查询路径**：
```
运单号 → 包裹(Package) → 直接获取状态信息
包裹编号 → 包裹轨迹(PackageTrack) → 按时间排序获取历史轨迹
```

---

#### 场景二：记录调度的历史记录和变更原因

**需求**：包裹在到达中转站时，由于天气变化需要调整后续路线。系统需要记录路线变更的历史，包括变更原因，能够查询历史路线规划详情和预计到达时间。

**模型支持**：
- ✅ **完全支持**
- 路径规划历史（RoutePlanHistory）实体专门用于记录路径变更
- 包含 `changeReason`（变更原因）、`changeTime`（变更时间）、`changeLocation`（变更位置）等关键属性
- 通过关联原路径规划和新路径规划，可以追溯完整的变更过程
- 路径规划实体包含 `plannedRoute`（规划路径）和 `estimatedTotalTime`（预计总时间）

**业务流程**：
1. 包裹到达中转站，检测到需要变更路线
2. 创建新路径规划，设置 `isCurrent=true`
3. 将原路径规划的 `isCurrent` 设置为 `false`
4. 创建路径规划历史记录，记录变更原因、时间、位置
5. 更新包裹的路径规划关联

**查询路径**：
```
包裹编号 → 路径规划历史(RoutePlanHistory) → 获取所有变更记录
路径规划历史 → 原路径规划/新路径规划(RoutePlan) → 获取规划详情
```

---

#### 场景三：车辆当前状态和在某一个中转站应该装载的包裹清单

**需求**：系统需要能够查询车辆当前的状态（当前位置、下一站、预计到达时间），以及车辆在某个中转站应该装载的包裹清单。

**模型支持**：
- ✅ **完全支持**
- 车辆实体直接包含 `currentLocation`（当前位置）、`nextStation`（下一站）、`estimatedArrivalTime`（预计到达时间）、`currentStatus`（当前状态）属性
- 通过车辆-运输任务-包裹的关联关系，可以查询车辆应该装载的包裹

**查询逻辑**：
1. **车辆状态查询**：直接通过车辆实体获取所有状态信息
2. **装载清单查询**：
   - 查询车辆关联的运输任务（TransportTask）
   - 筛选起点为指定中转站的运输任务
   - 获取这些运输任务关联的所有包裹（Package）
   - 这些包裹即为该车辆在该中转站应该装载的包裹清单

**查询路径**：
```
车辆编号 → 车辆(Vehicle) → 直接获取状态信息
车辆编号 → 运输任务(TransportTask) [起点=中转站] → 包裹(Package) → 装载清单
```

---

### 总结

| 场景 | 支持程度 | 关键实体 | 查询复杂度 |
|------|---------|---------|-----------|
| 包裹当前状态查询 | ✅ 完全支持 | 包裹、包裹轨迹 | 简单（直接属性查询） |
| 调度历史记录 | ✅ 完全支持 | 路径规划历史、路径规划 | 中等（关联查询） |
| 车辆状态和装载清单 | ✅ 完全支持 | 车辆、运输任务、包裹 | 中等（关联查询） |

**模型优势**：
1. **完整性**：覆盖包裹全生命周期的所有关键环节
2. **可追溯性**：完整记录历史轨迹和路径规划变更
3. **查询便利性**：关键信息直接存储在实体属性中，无需复杂计算
4. **扩展性**：支持未来可能的新需求
