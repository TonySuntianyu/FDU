## 概述

操作系统是现代计算机系统的核心，通过三个基本概念实现其功能：**虚拟化（Virtualization）**、**并发（Concurrency）**和**持久性（Persistence）**。本知识体系基于《Operating Systems: Three Easy Pieces》教材的核心理念，涵盖了操作系统从基础概念到具体实现的完整技术栈。

### 操作系统的三大核心概念

#### 1. 虚拟化（Virtualization）
- **CPU虚拟化**：通过时间片轮转让多个进程看似同时运行
- **内存虚拟化**：为每个进程提供独立的虚拟地址空间
- **I/O虚拟化**：将复杂的硬件设备抽象为简单的接口
- **目标**：让每个进程都认为自己独占整个计算机

### 虚拟化的发展历程
- **1960年代**：批处理系统的出现，实现了最早的资源抽象
- **1970年代**：分时系统的诞生，多用户虚拟化成为可能
- **1980年代**：个人计算机时代，单用户虚拟化技术成熟
- **1990年代**：网络虚拟化，分布式系统虚拟化
- **2000年代**：虚拟化技术商业化，VMware等虚拟化平台
- **2010年代**：容器化技术，Docker、Kubernetes等
- **2020年代**：云原生虚拟化，微服务架构

### 虚拟化的分类
- **硬件虚拟化**：CPU、内存、I/O设备的虚拟化
- **软件虚拟化**：操作系统、应用程序的虚拟化
- **网络虚拟化**：网络资源的抽象和隔离
- **存储虚拟化**：存储资源的统一管理和分配
- **桌面虚拟化**：用户界面的虚拟化
- **应用虚拟化**：应用程序的独立部署和运行

## 1. 抽象化基础

### 1.1 虚拟化本质
- **定义**：通过抽象层隐藏硬件复杂性，为用户和应用程序提供简化的接口
- **目标**：实现硬件无关的编程环境
- **核心**：将物理资源抽象为逻辑资源

#### 虚拟化的核心思想（基于Three Easy Pieces）
- **CPU虚拟化**：让每个进程都认为自己独占CPU
- **内存虚拟化**：让每个进程都认为自己独占内存
- **I/O虚拟化**：让每个进程都认为自己独占I/O设备
- **时间共享**：通过快速切换实现多进程并发执行
- **空间共享**：通过地址转换实现内存隔离

#### 虚拟化的实现原理
- **硬件支持**：利用硬件特性实现虚拟化
- **软件实现**：通过操作系统软件实现虚拟化
- **性能权衡**：在虚拟化效果和性能之间找到平衡
- **安全隔离**：确保不同进程间的安全隔离

### 1.2 抽象层次结构
```
应用程序层 (Application Layer)
    ↓ 系统调用接口
系统调用接口 (System Call Interface)
    ↓ 内核服务
操作系统内核 (Operating System Kernel)
    ↓ 硬件抽象
硬件抽象层 (Hardware Abstraction Layer)
    ↓ 直接控制
物理硬件 (Physical Hardware)
```

#### 各层次详细说明
- **应用程序层**：用户程序运行的环境，提供高级编程接口
- **系统调用接口**：用户态和内核态之间的桥梁，提供系统服务
- **操作系统内核**：核心功能实现，包括进程管理、内存管理、文件系统等
- **硬件抽象层**：屏蔽硬件差异，提供统一的硬件访问接口
- **物理硬件**：实际的计算机硬件，包括CPU、内存、存储、网络等

### 1.3 关键抽象

#### 进程抽象
- **定义**：将程序执行抽象为独立的进程
- **特点**：每个进程拥有独立的地址空间、文件描述符、信号处理等
- **实现**：通过进程控制块(PCB)管理进程状态
- **优势**：提供进程隔离、资源保护、并发执行

#### 文件系统抽象
- **定义**：将存储设备抽象为文件和目录结构
- **特点**：统一的文件操作接口，支持层次化目录结构
- **实现**：通过虚拟文件系统(VFS)提供统一接口
- **优势**：简化存储访问，支持多种文件系统类型

#### 网络抽象
- **定义**：将网络通信抽象为套接字接口
- **特点**：统一的网络编程接口，支持TCP/UDP协议
- **实现**：通过套接字API提供网络服务
- **优势**：简化网络编程，支持跨平台网络通信

#### 内存抽象
- **定义**：将物理内存抽象为虚拟地址空间
- **特点**：每个进程拥有独立的虚拟地址空间
- **实现**：通过地址转换机制实现虚拟内存
- **优势**：提供内存保护、支持大内存程序、实现内存共享

### 1.4 抽象化的实现机制

#### 硬件抽象层(HAL)
- **作用**：屏蔽硬件差异，提供统一的硬件访问接口
- **实现**：通过驱动程序实现硬件抽象
- **优势**：提高系统可移植性，简化硬件管理

#### 虚拟化技术
- **全虚拟化**：完全模拟硬件环境，客户操作系统无需修改
- **半虚拟化**：修改客户操作系统，提高性能
- **硬件辅助虚拟化**：利用CPU虚拟化指令，提高虚拟化效率

#### 容器化技术
- **定义**：操作系统级别的虚拟化技术
- **特点**：共享操作系统内核，轻量级虚拟化
- **优势**：资源利用率高，启动速度快，部署简单

## 2. API接口层

### 2.1 API的作用
- **标准化接口**：为应用程序提供统一的系统调用接口
- **资源访问控制**：通过API控制对系统资源的访问
- **抽象实现**：将底层硬件操作抽象为高级API调用

#### API的核心价值
- **简化编程**：将复杂的系统操作简化为简单的函数调用
- **提高可移植性**：统一的接口使程序可以在不同系统上运行
- **增强安全性**：通过API控制资源访问，防止非法操作
- **提高效率**：优化的系统调用实现，提高程序执行效率

### 2.2 主要API类型

#### 系统调用API
- **定义**：操作系统内核提供的底层服务接口
- **特点**：直接访问系统资源，执行特权操作
- **实现**：通过软中断或系统调用指令实现
- **分类**：
  - 进程管理：fork, exec, wait, exit, getpid, setuid
  - 文件操作：open, read, write, close, lseek, stat
  - 内存管理：mmap, munmap, brk, sbrk, mprotect
  - 网络通信：socket, bind, listen, accept, connect, send, recv
  - 信号处理：signal, sigaction, kill, alarm
  - 进程间通信：pipe, shmget, semget, msgget

#### 库函数API
- **定义**：标准库提供的函数接口
- **特点**：基于系统调用实现，提供更高级的功能
- **分类**：
  - 标准C库：stdio, stdlib, string, math
  - 数学库：三角函数、对数函数、随机数生成
  - 图形库：OpenGL, DirectX, X11
  - 网络库：Berkeley sockets, Winsock
  - 数据库库：SQLite, MySQL, PostgreSQL

#### 设备驱动API
- **定义**：硬件设备的抽象接口
- **特点**：屏蔽硬件差异，提供统一访问方式
- **分类**：
  - 块设备：磁盘、SSD、USB存储
  - 字符设备：键盘、鼠标、串口
  - 网络设备：网卡、调制解调器
  - 显示设备：显卡、显示器

### 2.3 系统调用详细分类

#### 进程控制类
- **fork()**：创建新进程，返回子进程PID
- **exec()**：执行新程序，替换当前进程映像
- **wait()**：等待子进程结束，获取退出状态
- **exit()**：终止当前进程，返回退出码
- **getpid()**：获取当前进程ID
- **getppid()**：获取父进程ID
- **setuid()**：设置用户ID
- **setgid()**：设置组ID

#### 文件操作类
- **open()**：打开文件，返回文件描述符
- **read()**：从文件读取数据
- **write()**：向文件写入数据
- **close()**：关闭文件描述符
- **lseek()**：移动文件指针
- **stat()**：获取文件状态信息
- **chmod()**：修改文件权限
- **unlink()**：删除文件

#### 内存管理类
- **mmap()**：内存映射文件或设备
- **munmap()**：取消内存映射
- **brk()**：调整堆空间大小
- **sbrk()**：增加堆空间
- **mprotect()**：修改内存页保护属性
- **mlock()**：锁定内存页
- **munlock()**：解锁内存页

#### 网络通信类
- **socket()**：创建套接字
- **bind()**：绑定地址到套接字
- **listen()**：监听连接请求
- **accept()**：接受连接请求
- **connect()**：连接到服务器
- **send()**：发送数据
- **recv()**：接收数据
- **shutdown()**：关闭套接字

#### 一致性原则

#### 安全性原则

- **访问控制**：基于用户权限的访问控制

#### 性能原则
- **最小开销**：减少系统调用开销
- **批量操作**：支持批量数据处理
- **异步操作**：支持非阻塞操作
- **缓存机制**：利用缓存提高性能

### 2.5 API实现机制

#### 系统调用实现
- **软中断**：通过软中断触发系统调用
- **系统调用表**：维护系统调用号到处理函数的映射
- **参数传递**：通过寄存器或栈传递参数
- **返回值**：通过寄存器返回结果

#### 库函数实现
- **封装系统调用**：基于系统调用实现高级功能
- **缓存机制**：实现数据缓存提高性能
- **错误处理**：统一的错误处理机制
- **内存管理**：自动内存管理功能

#### 系统调用实现示例
```c
// 简化的系统调用处理
void syscall_handler(int syscall_num, uint32_t arg1, uint32_t arg2, uint32_t arg3) {
    switch (syscall_num) {
        case SYS_FORK:
            // 创建新进程
            return sys_fork();
            
        case SYS_EXEC:
            // 执行新程序
            return sys_exec((char*)arg1);
            
        case SYS_WAIT:
            // 等待子进程
            return sys_wait((int*)arg1);
            
        case SYS_EXIT:
            // 退出进程
            sys_exit((int)arg1);
            break;
            
        case SYS_OPEN:
            // 打开文件
            return sys_open((char*)arg1, (int)arg2);
            
        case SYS_READ:
            // 读取文件
            return sys_read((int)arg1, (void*)arg2, (size_t)arg3);
            
        case SYS_WRITE:
            // 写入文件
            return sys_write((int)arg1, (void*)arg2, (size_t)arg3);
            
        case SYS_CLOSE:
            // 关闭文件
            return sys_close((int)arg1);
            
        default:
            return -1;  // 未知系统调用
    }
}

// 进程创建示例
pid_t sys_fork() {
    process_t *parent = current_process();
    process_t *child = create_process();
    
    // 复制父进程的地址空间
    copy_address_space(parent, child);
    
    // 设置子进程的返回值为0
    child->registers.eax = 0;
    parent->registers.eax = child->pid;
    
    // 将子进程加入就绪队列
    add_to_ready_queue(child);
    
    return child->pid;
}
```

## 3. 执行模型

### 3.1 执行虚拟化
- **进程虚拟化**：每个进程拥有独立的虚拟地址空间
- **CPU虚拟化**：通过时间片轮转实现多进程并发执行
- **内存虚拟化**：虚拟内存管理，地址转换

#### 进程虚拟化详解
- **地址空间隔离**：每个进程拥有独立的虚拟地址空间
- **资源隔离**：进程间无法直接访问彼此的资源
- **执行环境**：每个进程拥有独立的执行环境
- **状态管理**：独立的进程状态和上下文信息

#### CPU虚拟化详解
- **时间片轮转**：通过时间片实现多进程并发执行
- **优先级调度**：根据进程优先级分配CPU时间
- **抢占式调度**：高优先级进程可以抢占低优先级进程
- **负载均衡**：在多核系统中平衡CPU负载

#### 内存虚拟化详解
- **虚拟地址空间**：每个进程拥有独立的虚拟地址空间
- **地址转换**：虚拟地址到物理地址的映射
- **内存保护**：防止进程间非法内存访问
- **共享内存**：支持进程间内存共享

### 3.2 执行机制

#### 上下文切换
- **定义**：进程间的状态保存和恢复过程
- **触发条件**：时间片用完、系统调用、中断、异常
- **保存内容**：寄存器状态、程序计数器、栈指针、内存映射
- **性能影响**：上下文切换开销，影响系统性能
- **优化策略**：减少切换频率、优化切换过程、使用轻量级进程

#### 中断处理
- **硬件中断**：外部设备产生的中断信号
- **软件中断**：程序主动产生的中断
- **中断向量表**：中断号到处理函数的映射
- **中断优先级**：不同中断的优先级处理
- **中断嵌套**：高优先级中断可以打断低优先级中断处理

#### 异常处理
- **系统异常**：程序执行过程中的异常情况
- **异常类型**：除零异常、内存访问异常、指令异常
- **异常处理**：异常处理程序的执行
- **恢复机制**：异常处理后的程序恢复

### 3.3 进程状态转换
```
新建(New) → 就绪(Ready) → 运行(Running) → 阻塞(Blocked) → 终止(Terminated)
    ↑           ↓            ↓              ↓
    └───────────┴────────────┴──────────────┘
```

#### 状态详细说明
- **新建(New)**：进程刚被创建，尚未被调度
- **就绪(Ready)**：进程已准备好运行，等待CPU分配
- **运行(Running)**：进程正在CPU上执行
- **阻塞(Blocked)**：进程等待某个事件发生
- **终止(Terminated)**：进程执行完毕或被终止

#### 状态转换条件
- **新建→就绪**：进程创建完成，等待调度
- **就绪→运行**：进程被调度器选中，开始执行
- **运行→就绪**：时间片用完，进程被抢占
- **运行→阻塞**：进程等待I/O操作或同步事件
- **阻塞→就绪**：等待的事件发生，进程可以继续执行
- **运行→终止**：进程正常结束或被强制终止

### 3.4 进程控制块(PCB)

#### PCB结构
- **进程标识符**：进程ID、父进程ID、用户ID
- **处理器状态**：寄存器内容、程序计数器、栈指针
- **进程控制信息**：调度信息、进程状态、优先级
- **资源信息**：打开文件列表、内存映射、信号处理

#### PCB管理
- **创建**：进程创建时分配PCB
- **更新**：进程状态变化时更新PCB
- **销毁**：进程终止时释放PCB
- **查找**：根据进程ID查找PCB

### 3.5 进程创建和终止

#### 进程创建
- **fork()系统调用**：创建子进程
- **exec()系统调用**：执行新程序
- **进程继承**：子进程继承父进程的资源
- **资源分配**：为新进程分配必要的资源

#### 进程终止
- **正常终止**：进程执行完毕，调用exit()
- **异常终止**：进程遇到错误，被强制终止
- **资源回收**：释放进程占用的资源
- **状态通知**：通知父进程子进程的终止状态

### 3.6 进程间通信(IPC)

#### 通信方式
- **管道(Pipe)**：单向数据流，用于父子进程通信
- **命名管道(FIFO)**：有名称的管道，用于无关进程通信
- **消息队列**：异步消息传递机制
- **共享内存**：多个进程共享同一块内存区域
- **信号量**：进程同步机制
- **套接字**：网络通信机制

#### 通信特点
- **同步机制**：确保数据一致性
- **异步机制**：提高系统响应性
- **阻塞/非阻塞**：不同的通信模式
- **错误处理**：通信失败的处理机制

## 4. CPU调度虚拟化

### 4.1 调度基础

#### 调度的核心问题（基于Three Easy Pieces）
- **如何实现CPU虚拟化**：让多个进程看似同时运行
- **如何选择下一个进程**：调度算法的核心问题
- **如何实现时间共享**：通过快速切换实现并发
- **如何保证公平性**：确保所有进程都能获得CPU时间
- **如何优化性能**：在公平性和效率之间找到平衡

#### 调度目标
- **公平性**：确保所有进程获得公平的CPU时间
- **效率**：最大化系统吞吐量和响应时间
- **实时性**：满足实时任务的截止时间要求
- **响应性**：提高交互式应用的响应速度
- **吞吐量**：最大化单位时间内的作业完成数量

#### 调度策略

##### 先来先服务（FCFS）
- **原理**：按进程到达时间顺序调度
- **特点**：简单易实现，但可能导致长作业阻塞短作业
- **适用场景**：批处理系统
- **优缺点**：
  - 优点：实现简单，无饥饿现象
  - 缺点：平均等待时间长，不适合交互式系统

##### 短作业优先（SJF）
- **原理**：优先调度执行时间短的作业
- **特点**：理论上平均等待时间最短
- **适用场景**：已知作业执行时间的系统
- **优缺点**：
  - 优点：平均等待时间最短
  - 缺点：长作业可能饿死，需要预知执行时间

##### 时间片轮转（RR）
- **原理**：每个进程分配固定时间片，时间片用完则切换
- **特点**：公平性好，适合交互式系统
- **适用场景**：分时系统
- **优缺点**：
  - 优点：响应性好，公平性高
  - 缺点：时间片设置影响性能

##### 优先级调度
- **原理**：根据进程优先级进行调度
- **特点**：高优先级进程优先执行
- **适用场景**：实时系统
- **优缺点**：
  - 优点：满足实时性要求
  - 缺点：低优先级进程可能饿死

##### 多级反馈队列
- **原理**：多个优先级队列，进程在不同队列间移动
- **特点**：结合了多种调度策略的优点
- **适用场景**：通用操作系统
- **优缺点**：
  - 优点：兼顾响应性和公平性
  - 缺点：实现复杂，参数调优困难

### 4.2 多级反馈队列（MLFQ）

#### MLFQ原理
- **多级队列**：不同优先级的进程队列
- **动态调整**：根据进程行为动态调整优先级
- **反馈机制**：I/O密集型进程获得更高优先级

#### MLFQ详细机制

##### 队列结构
- **多级队列**：通常有3-5个优先级队列
- **优先级递减**：队列0优先级最高，队列N优先级最低
- **时间片递增**：高优先级队列时间片短，低优先级队列时间片长
- **队列管理**：每个队列维护就绪进程列表

##### 调度规则
1. **优先级比较**：如果A的优先级 > B的优先级，运行A
2. **同级轮转**：如果A的优先级 = B的优先级，轮转运行A和B
3. **初始优先级**：工作进入系统时，放在最高优先级
4. **优先级降低**：一旦工作用完了其在某一层中的时间配额，就降低其优先级
5. **优先级提升**：经过一段时间S，就将系统中所有工作重新加入最高优先级队列

##### 时间片分配
- **高优先级队列**：时间片短（1-4ms），适合交互式进程
- **中优先级队列**：时间片中等（8-16ms），适合混合型进程
- **低优先级队列**：时间片长（32-64ms），适合批处理进程

#### MLFQ参数调优

##### 关键参数
- **队列数量**：通常3-5个队列
- **时间片长度**：高优先级短，低优先级长
- **优先级提升时间**：定期提升所有进程优先级
- **I/O等待时间**：判断进程是否为I/O密集型

##### 调优策略
- **响应性调优**：减少高优先级队列时间片
- **吞吐量调优**：增加低优先级队列时间片
- **公平性调优**：调整优先级提升频率
- **负载均衡**：根据系统负载动态调整参数

#### MLFQ优势
- **响应性好**：交互式进程获得快速响应
- **公平性**：防止长作业饿死
- **适应性**：根据进程特征自动调整
- **灵活性**：支持多种进程类型

#### MLFQ缺点
- **参数敏感**：需要仔细调优参数
- **实现复杂**：需要维护多个队列
- **饥饿问题**：低优先级进程可能长期得不到执行
- **上下文切换**：频繁的优先级调整增加开销

#### MLFQ实现细节

##### 数据结构
```c
struct mlfq_queue {
    int priority;           // 队列优先级
    int time_slice;        // 时间片长度
    struct list_head ready; // 就绪进程列表
    int quantum_used;      // 已使用时间片
};

struct mlfq_scheduler {
    struct mlfq_queue queues[MAX_QUEUES];
    int current_queue;     // 当前调度队列
    int boost_interval;    // 优先级提升间隔
    int last_boost;        // 上次提升时间
};
```

##### 调度算法
1. **选择队列**：从最高优先级非空队列开始
2. **选择进程**：从队列中选择下一个进程
3. **时间片检查**：检查进程是否用完时间片
4. **优先级调整**：根据进程行为调整优先级
5. **定期提升**：定期提升所有进程优先级

##### 进程分类
- **交互式进程**：频繁I/O操作，需要快速响应
- **批处理进程**：CPU密集型，可以长时间运行
- **混合型进程**：既有I/O又有CPU操作
- **实时进程**：有严格时间要求的进程

#### MLFQ调度算法实现示例
```c
// MLFQ调度器实现
typedef struct {
    int priority;           // 队列优先级
    int time_slice;        // 时间片长度
    list_t ready_queue;    // 就绪进程队列
} mlfq_queue_t;

typedef struct {
    mlfq_queue_t queues[MAX_QUEUES];
    int current_queue;
    int boost_interval;
    int last_boost;
} mlfq_scheduler_t;

// 调度下一个进程
process_t* mlfq_schedule(mlfq_scheduler_t *scheduler) {
    // 定期提升所有进程优先级
    if (current_time - scheduler->last_boost > scheduler->boost_interval) {
        mlfq_boost_all_processes(scheduler);
        scheduler->last_boost = current_time;
    }
    
    // 从最高优先级非空队列选择进程
    for (int i = 0; i < MAX_QUEUES; i++) {
        if (!list_empty(&scheduler->queues[i].ready_queue)) {
            return list_remove_head(&scheduler->queues[i].ready_queue);
        }
    }
    
    return NULL;  // 没有就绪进程
}

// 进程时间片用完，降低优先级
void mlfq_time_slice_expired(process_t *process, mlfq_scheduler_t *scheduler) {
    if (process->current_queue < MAX_QUEUES - 1) {
        process->current_queue++;
        list_add_tail(&scheduler->queues[process->current_queue].ready_queue, process);
    }
}
```

### 4.3 比例共享调度

#### 比例共享概念
- **权重分配**：根据进程重要性分配CPU时间比例
- **公平调度**：确保每个进程获得其应得的CPU时间
- **动态调整**：根据系统负载动态调整权重

#### 比例共享调度原理

##### 基本思想
- **权重表示**：每个进程有一个权重值，表示其应得的CPU时间比例
- **公平分配**：CPU时间按权重比例分配给各进程
- **动态调整**：根据进程行为动态调整权重

##### 权重计算
- **静态权重**：进程创建时设定的固定权重
- **动态权重**：根据进程行为动态调整的权重
- **相对权重**：相对于其他进程的权重比例
- **绝对权重**：进程的绝对权重值

#### 实现方法

##### 彩票调度（Lottery Scheduling）
- **原理**：每个进程获得与其权重成比例的彩票数量
- **调度过程**：随机抽取彩票，中奖进程获得CPU时间
- **优点**：实现简单，公平性好
- **缺点**：随机性可能导致不公平

##### 彩票调度实现
```c

    int start_ticket;
    int end_ticket;
};

    struct lottery_ticket tickets[MAX_PROCESSES];
    int total_tickets;
    int current_ticket;
};
```

##### 步长调度（Stride Scheduling）
- **原理**：每个进程有一个步长值，步长值越小，优先级越高
- **调度过程**：选择步长值最小的进程执行
- **优点**：确定性调度，公平性好
- **缺点**：实现复杂，需要维护步长值

##### 步长调度实现

##### 公平共享（Fair Share）
- **原理**：基于虚拟时间的公平调度
- **调度过程**：选择虚拟时间最小的进程执行
- **优点**：理论公平性最好
- **缺点**：实现复杂，计算开销大

#### 比例共享调度算法

##### 权重分配策略
- **用户权重**：不同用户获得不同的CPU时间比例
- **进程权重**：同一用户的不同进程获得不同权重
- **动态权重**：根据进程行为动态调整权重
- **优先级权重**：结合优先级和权重的混合调度

##### 公平性保证
- **短期公平**：在短时间内保证公平性
- **长期公平**：在长时间内保证公平性

##### 性能优化

- **缺点**：可能浪费大块内存

### 5.3 地址转换

#### 地址转换机制
- **页表**：虚拟地址到物理地址的映射表
- **TLB**：地址转换缓存，提高转换效率
- **多级页表**：减少页表空间占用

#### 地址转换过程
```
虚拟地址 → 页表查找 → 物理地址
    ↓
TLB查找（命中则直接返回）
    ↓
页表缺失处理
```

#### 地址转换示例
```c
// 简化的地址转换过程
uint32_t virtual_to_physical(uint32_t virtual_addr, page_table_t *pt) {
    uint32_t page_num = virtual_addr >> 12;        // 页号
    uint32_t offset = virtual_addr & 0xFFF;        // 页内偏移
    
    // 检查TLB
    if (tlb_lookup(page_num, &physical_page)) {
        return (physical_page << 12) | offset;
    }
    
    // 查找页表
    page_table_entry_t *entry = &pt->entries[page_num];
    if (!entry->valid) {
        handle_page_fault(virtual_addr);
    }
    
    // 更新TLB
    tlb_update(page_num, entry->physical_page);
    
    return (entry->physical_page << 12) | offset;
}
```

#### 地址转换详细机制

##### 页表结构
- **页表项**：每个页表项包含物理页号和保护位
- **页表大小**：页表大小取决于虚拟地址空间大小
- **页表位置**：页表存储在内存中，由页表基址寄存器指向
- **页表更新**：页表内容由操作系统维护

##### 地址转换步骤
1. **虚拟地址分解**：将虚拟地址分解为页号和页内偏移
2. **页表查找**：根据页号查找页表项
3. **物理地址计算**：物理页号 + 页内偏移 = 物理地址
4. **权限检查**：检查访问权限是否允许
5. **异常处理**：处理页表缺失等异常情况

##### 页表缺失处理
- **页表缺失**：页表项不存在或无效
- **页面缺失**：物理页面不存在
- **权限违规**：访问权限不足
- **异常处理**：操作系统处理各种异常情况

#### 地址转换优化

##### TLB（转换后备缓冲区）
- **作用**：缓存常用的地址转换结果
- **结构**：TLB条目包含虚拟页号和物理页号
- **查找**：并行查找TLB中的条目
- **更新**：TLB内容与页表保持同步

##### TLB管理

- **TLB一致性**：保持TLB与页表的一致性
- **TLB替换**：TLB满时的替换策略

### 6.2 交换策略

#### 置换算法

##### FIFO（先进先出）
- **原理**：按页面进入内存的时间顺序置换
- **优点**：实现简单，无饥饿现象
- **缺点**：可能置换常用页面
- **适用场景**：页面访问模式随机的系统

##### LRU（最近最少使用）
- **原理**：置换最近最少使用的页面
- **优点**：理论上性能最好
- **缺点**：实现复杂，需要硬件支持
- **适用场景**：页面访问有局部性的系统

##### LFU（最少使用频率）
- **原理**：置换使用频率最低的页面
- **优点**：考虑页面使用频率
- **缺点**：可能置换常用页面
- **适用场景**：页面使用频率差异大的系统

##### Clock算法
- **原理**：改进的LRU算法，使用访问位
- **优点**：实现相对简单，性能较好
- **缺点**：可能置换常用页面
- **适用场景**：通用操作系统

#### 页面置换过程
```
页面访问 → 检查是否在内存中
    ↓
在内存中：直接访问
    ↓
不在内存中：页面错误
    ↓
选择置换页面 → 写回磁盘 → 读入新页面
```

### 8.2 多处理器调度策略

#### 调度策略类型

##### 全局队列
- **单一队列**：所有CPU共享一个就绪队列
- **优点**：负载均衡好，实现简单
- **缺点**：锁竞争激烈，扩展性差
- **适用场景**：小规模多核系统

##### 本地队列
- **独立队列**：每个CPU维护独立的就绪队列
- **优点**：锁竞争少，扩展性好
- **缺点**：负载均衡困难
- **适用场景**：大规模多核系统

##### 混合队列
- **分层队列**：全局队列 + 本地队列
- **优点**：兼顾负载均衡和性能
- **缺点**：实现复杂
- **适用场景**：中等规模多核系统
