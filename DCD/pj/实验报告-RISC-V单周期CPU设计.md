## 摘要

本实验设计并实现了一个基于RISC-V指令集的32位单周期CPU，支持9条基本指令（add、sub、or、slt、addi、ori、slti、lw、sw）和1条分支指令（beq）。通过Verilog HDL完成了ALU、寄存器堆、存储器、控制单元等关键部件的设计，并在Vivado仿真平台上验证了所有指令的正确执行。实验结果表明，设计的CPU能够正确完成指令的取指、译码、执行、访存和写回五个阶段，所有寄存器和存储器的值均符合预期。本报告详细介绍了CPU的整体架构、各模块的设计思路、仿真测试过程以及性能分析，并提出了进一步优化的建议。

## 2. 设计方案

### 2.1 CPU总体架构

本设计采用经典的单周期数据通路结构，每条指令在一个时钟周期内完成全部五个阶段：取指（IF）、译码（ID）、执行（EX）、访存（MEM）、写回（WB）。

#### 2.1.1 架构框图

```
┌─────────────────────────────────────────────────────────────────┐
│                        单周期CPU架构                              │
└─────────────────────────────────────────────────────────────────┘

              ┌──────┐
              │  PC  │ ◄─────────┐
              └──┬───┘           │
                 │                │
                 ▼                │
          ┌────────────┐          │
          │  Program   │          │
          │  Memory    │          │
          │  (256B)    │          │
          └─────┬──────┘          │
                │                 │
          Instruction             │
                │                 │
                ▼                 │
          ┌────────────┐          │
          │  Control   │          │
          │   Unit     │          │
          └─────┬──────┘          │
                │                 │
          Control Signals         │
                │                 │
    ┌───────────┼───────────┐     │
    │           │           │     │
    ▼           ▼           ▼     │
┌────────┐  ┌────────┐  ┌────────┐
│ImmGen  │  │Register│  │  ALU   │
│        │  │  File  │  │        │
└───┬────┘  │ (32x32)│  └───┬────┘

                │
                └──────────────────┘
```

#### 2.1.2 关键部件说明

1. **PC（Program Counter）**：存储当前指令地址，每周期更新
2. **程序存储器（PM）**：存储指令代码，只读
3. **控制单元（CU）**：根据指令生成控制信号
4. **立即数生成器（ImmGen）**：提取并扩展立即数
5. **寄存器堆（RF）**：存储32个通用寄存器
6. **ALU**：执行算术和逻辑运算
7. **数据存储器（DM）**：存储程序数据，可读写
8. **多路选择器（MUX）**：根据控制信号选择数据通路

### 2.2 指令格式

本CPU支持RISC-V指令集的四种基本格式：

#### 2.2.1 R型指令格式

```
31      25 24   20 19   15 14  12 11    7 6      0
┌─────────┬───────┬───────┬──────┬───────┬────────┐
│ funct7  │  rs2  │  rs1  │funct3│  rd   │ opcode │
└─────────┴───────┴───────┴──────┴───────┴────────┘
  7 bits    5 bits  5 bits  3 bits 5 bits  7 bits

示例：add X3, X1, X2 → 0x002081B3
```

#### 2.2.2 I型指令格式

```
31            20 19   15 14  12 11    7 6      0
┌───────────────┬───────┬──────┬───────┬────────┐
│   imm[11:0]   │  rs1  │funct3│  rd   │ opcode │
└───────────────┴───────┴──────┴───────┴────────┘
    12 bits      5 bits  3 bits 5 bits  7 bits

示例：addi X1, X0, 8 → 0x00800093
```

#### 2.2.3 S型指令格式

```
31      25 24   20 19   15 14  12 11    7 6      0
┌─────────┬───────┬───────┬──────┬───────┬────────┐
│imm[11:5]│  rs2  │  rs1  │funct3│imm[4:0]│ opcode │
└─────────┴───────┴───────┴──────┴───────┴────────┘
  7 bits    5 bits  5 bits  3 bits 5 bits  7 bits

示例：sw X6, 0(X2) → 0x00612023
```

#### 2.2.4 B型指令格式

```
31 30    25 24   20 19   15 14  12 11   8 7 6      0
┌──┬───────┬───────┬───────┬──────┬──────┬─┬────────┐
│im│imm[10:│  rs2  │  rs1  │funct3│imm[4:│i│ opcode │
│12│  5]   │       │       │      │  1]  │1│        │
└──┴───────┴───────┴───────┴──────┴──────┴─┴────────┘

示例：beq X3, X5, -12 → 0xFE518AE3
```

### 2.3 控制信号定义

| 控制信号 | 位宽 | 功能说明 |
|---------|------|---------|
| RegWrite | 1 | 寄存器写使能：1=写入，0=不写 |
| MemWrite | 1 | 存储器写使能：1=写入，0=不写 |
| MemRead | 1 | 存储器读使能：1=读取，0=不读 |
| MemtoReg | 1 | 写回数据源：1=存储器，0=ALU |
| ALUSrc | 1 | ALU第二操作数：1=立即数，0=寄存器 |
| Branch | 1 | 分支指令标志：1=分支，0=顺序 |
| ALUOp[3:0] | 4 | ALU操作码：0000=加，0001=减，0010=或，0011=比较 |

### 2.4 数据通路设计

#### 2.4.1 取指阶段（IF）
1. PC输出当前指令地址
2. 程序存储器根据地址读取32位指令
3. 指令送入后续阶段

#### 2.4.2 译码阶段（ID）
1. 控制单元解析opcode、funct3、funct7
2. 生成所有控制信号
3. 立即数生成器提取并扩展立即数
4. 寄存器堆读取源操作数

#### 2.4.3 执行阶段（EX）
1. ALU根据ALUOp执行相应运算
2. 计算存储器访问地址（lw/sw）
3. 计算分支目标地址（beq）
4. 生成零标志位Zero

#### 2.4.4 访存阶段（MEM）
1. lw指令：从数据存储器读取数据
2. sw指令：向数据存储器写入数据
3. 其他指令：跳过此阶段

#### 2.4.5 写回阶段（WB）
1. 根据MemtoReg选择写回数据源
2. 在时钟上升沿写入目标寄存器
3. 同时更新PC值

## 3. 模块设计与实现

### 3.1 ALU模块（算术逻辑单元）

#### 3.1.1 功能描述

ALU负责执行所有算术和逻辑运算，是CPU的核心计算部件。

**支持的操作：**
- **ADD**（0000）：无符号/有符号加法
- **SUB**（0001）：无符号/有符号减法
- **OR**（0010）：按位逻辑或
- **SLT**（0011）：有符号数比较

#### 3.1.2 接口定义

```verilog
module ALU(
    input [31:0] A,          // 操作数A
    input [31:0] B,          // 操作数B
    input [3:0] ALUOp,       // ALU操作码
    output reg [31:0] Result, // 运算结果
    output Zero              // 零标志位
);
```

#### 3.1.3 实现要点

1. **运算实现**：使用case语句根据ALUOp选择运算类型
2. **有符号比较**：使用`$signed()`进行有符号数比较
3. **零标志**：用于beq指令的条件判断

#### 3.1.4 关键代码

```verilog
always @(*) begin
    case(ALUOp)
        4'b0000: Result = A + B;           // 加法
        4'b0001: Result = A - B;           // 减法
        4'b0010: Result = A | B;           // 逻辑或
        4'b0011: Result = ($signed(A) < $signed(B)) ? 32'd1 : 32'd0; // 比较
        default: Result = 32'd0;
    endcase
end

assign Zero = (Result == 32'd0);  // 零标志
```

### 3.2 寄存器堆模块（RegisterFile）

#### 3.2.1 功能描述

寄存器堆包含32个32位通用寄存器，支持同时读取两个寄存器和写入一个寄存器。

**特殊规则：**
- X0寄存器恒为0，任何写入操作无效
- 读操作为组合逻辑，立即生效
- 写操作在时钟上升沿同步进行

#### 3.2.2 接口定义

```verilog
module RegisterFile(
    input clk,                  // 时钟信号
    input rst,                  // 复位信号
    input RegWrite,             // 写使能
    input [4:0] ReadReg1,       // 读端口1地址
    input [4:0] ReadReg2,       // 读端口2地址
    input [4:0] WriteReg,       // 写端口地址
    input [31:0] WriteData,     // 写入数据
    output [31:0] ReadData1,    // 读端口1数据
    output [31:0] ReadData2     // 读端口2数据
);
```

#### 3.2.3 实现要点

1. **X0特殊处理**：读X0时强制返回0，写X0时忽略
2. **双端口读**：支持同时读取两个不同寄存器
3. **同步写**：在时钟上升沿写入，避免竞争冒险

#### 3.2.4 关键代码

```verilog
// 32个32位寄存器
reg [31:0] registers [0:31];

// 写操作（同步）
always @(posedge clk or posedge rst) begin
    if (rst) begin
        // 复位时清零所有寄存器
        for (i = 0; i < 32; i = i + 1)
            registers[i] <= 32'd0;
    end
    else if (RegWrite && WriteReg != 5'd0) begin
        // 不允许写入X0
        registers[WriteReg] <= WriteData;
    end
end

// 读操作（组合逻辑）
assign ReadData1 = (ReadReg1 == 5'd0) ? 32'd0 : registers[ReadReg1];
assign ReadData2 = (ReadReg2 == 5'd0) ? 32'd0 : registers[ReadReg2];
```

### 3.3 程序存储器模块（ProgramMemory）

#### 3.3.1 功能描述

程序存储器用于存储指令代码，容量为256字节，采用小端模式存储。

**特性：**
- 只读存储器（ROM）
- 按字节寻址，每次读取32位
- 使用initial块初始化测试程序

#### 3.3.2 接口定义

```verilog
module ProgramMemory(
    input [7:0] Address,        // 字节地址（0-255）
    output [31:0] Instruction   // 32位指令
);
```

#### 3.3.3 实现要点

1. **小端模式**：低字节存储在低地址
2. **初始化**：使用initial块加载测试程序
3. **组合读取**：读操作为组合逻辑，无延迟

#### 3.3.4 测试程序

```verilog
initial begin
    // 指令1: addi X1, X0, 8 (0x00800093)
    memory[0] = 8'h93; memory[1] = 8'h00;
    memory[2] = 8'h80; memory[3] = 8'h00;
    
    // 指令2: lw X2, 4(X1) (0x0040a103)
    memory[4] = 8'h03; memory[5] = 8'ha1;
    memory[6] = 8'h40; memory[7] = 8'h00;
    
    // ... 其他指令
end

// 小端模式读取
assign Instruction = {memory[Address+3], memory[Address+2],
                     memory[Address+1], memory[Address]};
```

### 3.4 数据存储器模块（DataMemory）

#### 3.4.1 功能描述

数据存储器用于存储程序数据，容量为256字节，支持读写操作。

**特性：**
- 可读可写存储器（RAM）
- 采用小端模式
- 写操作在时钟上升沿同步进行
- 读操作为组合逻辑

#### 3.4.2 接口定义

```verilog
module DataMemory(
    input clk,                  // 时钟信号
    input MemWrite,             // 写使能
    input MemRead,              // 读使能
    input [7:0] Address,        // 字节地址
    input [31:0] WriteData,     // 写入数据
    output [31:0] ReadData      // 读出数据
);
```

#### 3.4.3 实现要点

1. **初始化**：预置部分测试数据
2. **小端写入**：将32位数据分解为4个字节
3. **小端读取**：将4个字节组合为32位数据

#### 3.4.4 关键代码

```verilog
// 初始化（用于lw指令测试）
initial begin
    for (i = 0; i < 16; i = i + 1)
        memory[i] = i[7:0];  // 地址0-15存储0-15
    for (i = 16; i < 256; i = i + 1)
        memory[i] = 8'h00;
end

// 写操作（小端模式）
always @(posedge clk) begin
    if (MemWrite) begin
        memory[Address]   <= WriteData[7:0];
        memory[Address+1] <= WriteData[15:8];
        memory[Address+2] <= WriteData[23:16];
        memory[Address+3] <= WriteData[31:24];
    end
end

// 读操作（小端模式）
assign ReadData = MemRead ? {memory[Address+3], memory[Address+2],
                            memory[Address+1], memory[Address]} : 32'd0;
```

### 3.5 控制单元模块（ControlUnit）

#### 3.5.1 功能描述

控制单元是CPU的"大脑"，根据指令的opcode、funct3、funct7生成所有控制信号。

#### 3.5.2 接口定义

```verilog
module ControlUnit(
    input [6:0] opcode,         // 操作码
    input [2:0] funct3,         // 功能码3
    input [6:0] funct7,         // 功能码7
    output reg RegWrite,        // 寄存器写使能
    output reg MemWrite,        // 存储器写使能
    output reg MemRead,         // 存储器读使能
    output reg MemtoReg,        // 存储器数据写回
    output reg ALUSrc,          // ALU操作数源
    output reg Branch,          // 分支标志
    output reg [3:0] ALUOp      // ALU操作码
);
```

#### 3.5.3 控制信号真值表

| 指令类型 | opcode | RegWrite | MemWrite | MemRead | MemtoReg | ALUSrc | Branch | ALUOp |
|---------|--------|----------|----------|---------|----------|--------|--------|-------|
| R型 | 0110011 | 1 | 0 | 0 | 0 | 0 | 0 | 根据funct |
| I型算术 | 0010011 | 1 | 0 | 0 | 0 | 1 | 0 | 根据funct3 |
| lw | 0000011 | 1 | 0 | 1 | 1 | 1 | 0 | ADD |
| sw | 0100011 | 0 | 1 | 0 | X | 1 | 0 | ADD |
| beq | 1100011 | 0 | 0 | 0 | X | 0 | 1 | SUB |

#### 3.5.4 实现要点

```verilog
always @(*) begin
    // 默认值
    RegWrite = 0; MemWrite = 0; MemRead = 0;
    MemtoReg = 0; ALUSrc = 0; Branch = 0;
    ALUOp = 4'b0000;
    
    case(opcode)
        7'b0110011: begin  // R型
            RegWrite = 1;
            ALUSrc = 0;
            case({funct7, funct3})
                10'b0000000_000: ALUOp = 4'b0000;  // add
                10'b0100000_000: ALUOp = 4'b0001;  // sub
                10'b0000000_110: ALUOp = 4'b0010;  // or
                10'b0000000_010: ALUOp = 4'b0011;  // slt
            endcase
        end
        
        7'b0010011: begin  // I型算术
            RegWrite = 1;
            ALUSrc = 1;
            case(funct3)
                3'b000: ALUOp = 4'b0000;  // addi
                3'b110: ALUOp = 4'b0010;  // ori
                3'b010: ALUOp = 4'b0011;  // slti
            endcase
        end
        
        7'b0000011: begin  // lw
            RegWrite = 1; MemRead = 1;
            MemtoReg = 1; ALUSrc = 1;
            ALUOp = 4'b0000;  // 地址计算
        end
        
        7'b0100011: begin  // sw
            MemWrite = 1; ALUSrc = 1;
            ALUOp = 4'b0000;  // 地址计算
        end
        
        7'b1100011: begin  // beq
            Branch = 1; ALUSrc = 0;
            ALUOp = 4'b0001;  // 减法比较
        end
    endcase
end
```

### 3.6 立即数生成模块（ImmGen）

#### 3.6.1 功能描述

立即数生成器从指令中提取立即数字段，并进行符号扩展至32位。

#### 3.6.2 实现要点

不同类型指令的立即数位置不同：
- **I型**：inst[31:20]，12位符号扩展
- **S型**：{inst[31:25], inst[11:7]}，12位符号扩展
- **B型**：{inst[31], inst[7], inst[30:25], inst[11:8], 1'b0}，13位符号扩展

```verilog
always @(*) begin
    case(opcode)
        7'b0010011, 7'b0000011: begin  // I型
            Immediate = {{20{Instruction[31]}}, Instruction[31:20]};
        end
        7'b0100011: begin  // S型
            Immediate = {{20{Instruction[31]}}, 
                        Instruction[31:25], Instruction[11:7]};
        end
        7'b1100011: begin  // B型
            Immediate = {{19{Instruction[31]}}, Instruction[31],
                        Instruction[7], Instruction[30:25],
                        Instruction[11:8], 1'b0};
        end
        default: Immediate = 32'd0;
    endcase
end
```

### 3.7 CPU顶层模块

#### 3.7.1 模块整合

CPU顶层模块将所有子模块连接起来，形成完整的数据通路。

```verilog
module CPU(
    input clk,              // 时钟信号
    input rst               // 复位信号
);
    // PC寄存器
    reg [31:0] PC;
    
    // 内部信号
    wire [31:0] Instruction, Immediate;
    wire [31:0] ReadData1, ReadData2, WriteData;
    wire [31:0] ALU_A, ALU_B, ALU_Result;
    wire [31:0] MemReadData;
    wire [31:0] PC_Next, PC_Branch;
    wire RegWrite, MemWrite, MemRead, MemtoReg;
    wire ALUSrc, Branch, Zero, PCSrc;
    wire [3:0] ALUOp;
    wire [4:0] rs1, rs2, rd;
    
    // 提取指令字段
    assign rs1 = Instruction[19:15];
    assign rs2 = Instruction[24:20];
    assign rd  = Instruction[11:7];
    
    // PC更新逻辑
    always @(posedge clk or posedge rst) begin
        if (rst)
            PC <= 32'd0;
        else
            PC <= PC_Next;
    end
    
    // PC跳转控制
    assign PCSrc = Branch & Zero;
    assign PC_Branch = PC + Immediate;
    assign PC_Next = PCSrc ? PC_Branch : (PC + 4);
    
    // 模块实例化
    ProgramMemory PM(...);
    ControlUnit CU(...);
    ImmGen IG(...);
    RegisterFile RF(...);
    ALU alu(...);
    DataMemory DM(...);
    
    // 数据通路连接
    assign ALU_A = ReadData1;
    assign ALU_B = ALUSrc ? Immediate : ReadData2;
    assign WriteData = MemtoReg ? MemReadData : ALU_Result;
endmodule
```

## 5. 性能分析

### 5.1 时钟周期分析

#### 5.1.1 关键路径识别

单周期CPU的时钟周期必须满足最长指令路径的延迟要求。通过分析各条指令的数据通路，最长路径为**lw指令**：

```
PC → PM → CU → RF → ALU → DM → MUX → RF
```

**路径延迟估算：**

| 部件 | 延迟（ns） | 说明 |
|------|-----------|------|
| PC寄存器输出 | 1 | 寄存器读取 |
| 程序存储器（PM） | 5 | SRAM读取 |
| 控制单元（CU） | 2 | 组合逻辑译码 |
| 寄存器堆读取（RF） | 3 | 寄存器读取 |
| ALU运算 | 5 | 32位加法器 |
| 数据存储器（DM） | 5 | SRAM读取 |
| 写回选择器（MUX） | 1 | 2选1多路选择器 |
| 寄存器建立时间 | 2 | D触发器建立时间 |

**总延迟：1 + 5 + 2 + 3 + 5 + 5 + 1 + 2 = 24ns**

#### 5.1.2 最高工作频率

基于关键路径延迟24ns，理论最高工作频率为：

```
f_max = 1 / T_critical = 1 / 24ns ≈ 41.67 MHz
```

**实际设计采用50MHz（周期20ns）需要优化或使用更快的存储器。**

### 5.2 CPI分析

#### 5.2.1 CPI定义

CPI（Cycles Per Instruction）表示每条指令平均需要的时钟周期数。

**单周期CPU的特点：**
- 每条指令固定占用1个时钟周期
- **CPI = 1.0**（理想值）

#### 5.2.2 各指令周期数

| 指令类型 | 周期数 | 说明 |
|---------|--------|------|
| R型（add, sub, or, slt） | 1 | 单周期 |
| I型算术（addi, ori, slti） | 1 | 单周期 |
| I型加载（lw） | 1 | 单周期（尽管有访存） |
| S型存储（sw） | 1 | 单周期 |
| B型分支（beq） | 1 | 单周期 |

**所有指令CPI = 1.0**

#### 5.2.3 性能计算

假设测试程序执行N次（不含循环），总时钟周期数：

```
总周期数 = 指令数 × CPI = 10 × 1 = 10个周期
执行时间 = 10 × 20ns = 200ns（@50MHz）
```

### 5.3 资源利用率分析

#### 5.3.1 时间维度利用率

分析各部件在不同指令中的使用情况：

| 部件 | R型 | I型算术 | lw | sw | beq | 利用率 |
|------|-----|---------|----|----|-----|--------|
| PC | ✓ | ✓ | ✓ | ✓ | ✓ | 100% |
| PM | ✓ | ✓ | ✓ | ✓ | ✓ | 100% |
| CU | ✓ | ✓ | ✓ | ✓ | ✓ | 100% |
| RF（读） | ✓ | ✓ | ✓ | ✓ | ✓ | 100% |
| RF（写） | ✓ | ✓ | ✓ | ✗ | ✗ | 70% |
| ALU | ✓ | ✓ | ✓ | ✓ | ✓ | 100% |
| DM（读） | ✗ | ✗ | ✓ | ✗ | ✗ | 10% |
| DM（写） | ✗ | ✗ | ✗ | ✓ | ✗ | 10% |

**分析：**
- 必需部件（PC、PM、CU、ALU）利用率100%
- 存储器利用率很低（10%），存在优化空间

#### 5.3.2 空间维度资源占用

**寄存器资源：**
- 总数：32个 × 32位 = 1024位
- 实际使用：9个（X0-X8）
- 利用率：9/32 = 28.125%

**存储器资源：**
- 程序存储器：256字节，使用40字节
- 数据存储器：256字节，使用约16字节
- 利用率：约6-16%

### 5.4 功耗分析（定性）

#### 5.4.1 动态功耗

单周期CPU的主要功耗来源：

1. **时钟网络**：驱动所有时序元件
2. **存储器访问**：每周期访问PM，部分周期访问DM
3. **ALU运算**：每周期都工作
4. **寄存器堆**：每周期读写操作

**特点：**
- 所有部件每周期都被激活，即使不需要
- 功耗较高，效率较低

#### 5.4.2 静态功耗

- 主要来自晶体管漏电流
- 与工艺和设计无关

## 6. 改进方案与展望

### 6.1 性能优化方案

#### 6.1.1 流水线化

**基本思路：**
将单周期CPU改造为5级流水线结构：

```
IF（取指） → ID（译码） → EX（执行） → MEM（访存） → WB（写回）
```

**预期改进：**
- 时钟周期缩短至5ns（约5倍提升）
- 理论吞吐量提升5倍
- 最高频率可达200MHz

**需要解决的问题：**
1. **数据冒险**：
   - 前递（Forwarding）机制
   - 流水线暂停（Stall）
   
2. **控制冒险**：
   - 分支预测
   - 延迟槽技术
   
3. **结构冒险**：
   - 哈佛架构（分离指令和数据存储器）

#### 6.1.2 Cache优化

**问题**：
当前设计中存储器访问延迟占关键路径的40%以上。

**解决方案：**
1. **一级Cache**：
   - 指令Cache（I-Cache）：32KB，直接映射
   - 数据Cache（D-Cache）：32KB，直接映射
   - 命中时延迟仅1-2ns
   
2. **预期效果**：
   - Cache命中率>95%
   - 平均访存延迟降至1.5ns
   - 时钟周期缩短至15ns

#### 6.1.3 分支预测

**问题**：
beq指令需要等到EX阶段才能确定跳转，浪费流水线周期。

**改进方案：**
1. **静态预测**：
   - 预测总是不跳转（BTFN）
   - 或预测总是跳转（BTFT）
   
2. **动态预测**：
   - 1位预测器：记录上次跳转结果
   - 2位预测器：需连续两次错误才改变预测
   
3. **分支目标缓冲**：
   - BTB（Branch Target Buffer）
   - 缓存分支指令的目标地址

**预期效果：**
- 分支预测准确率>85%
- 平均减少0.3个周期损失

### 6.2 功能扩展方案

#### 6.2.1 完整RV32I指令集

当前仅实现10条指令，可扩展至完整的RV32I（47条指令）：

**需要添加的指令：**

1. **算术指令**：
   - `sll`, `srl`, `sra`（移位指令）
   - `xor`, `and`（逻辑指令）
   
2. **跳转指令**：
   - `jal`, `jalr`（无条件跳转）
   
3. **分支指令**：
   - `bne`, `blt`, `bge`, `bltu`, `bgeu`
   
4. **加载/存储指令**：
   - `lb`, `lh`, `lbu`, `lhu`（字节、半字加载）
   - `sb`, `sh`（字节、半字存储）
   
5. **立即数指令**：
   - `lui`, `auipc`（大立即数）

**修改要点：**
- 扩展ALU操作码至6-8位
- 修改控制单元真值表
- 添加移位器模块

#### 6.2.2 中断和异常处理

**基本思路：**
1. **中断控制器**：
   - 响应外部中断请求
   - 优先级仲裁
   
2. **异常处理**：
   - 非法指令异常
   - 地址对齐异常
   - 溢出异常
   
3. **特殊寄存器**：
   - CSR（Control and Status Registers）
   - `mtvec`：中断向量表基址
   - `mepc`：异常返回地址
   - `mcause`：异常原因

#### 6.2.3 特权级支持

实现M模式（Machine Mode）和U模式（User Mode）：
- 内存保护机制（PMP）
- 系统调用指令（ecall）
- 特权指令（mret）

### 6.3 硬件优化方案

#### 6.3.1 面积优化

**目标**：减少硬件资源占用

**方法：**
1. **资源共享**：
   - 多周期设计中复用ALU
   - 复用加法器做地址计算
   
2. **编码优化**：
   - 控制信号编码压缩
   - 减少多路选择器位宽

#### 6.3.2 功耗优化

**方法：**
1. **时钟门控**：
   - 不使用的模块关闭时钟
   - 降低动态功耗50%以上
   
2. **电源门控**：
   - 长期不用的模块切断电源
   - 降低静态功耗
   
3. **低功耗设计技术**：
   - 多电压域
   - 动态电压频率调节（DVFS）

#### 6.3.3 可靠性优化

**方法：**
1. **ECC（Error Correction Code）**：
   - 寄存器和存储器添加ECC

### 7.2 遇到的问题与解决

#### 7.2.1 小端模式实现

**问题描述**：
最初设计时没有注意到小端模式的要求，导致指令读取错误。

**解决方法**：
```verilog
// 错误：大端模式
assign Instruction = {memory[Address], memory[Address+1],
                     memory[Address+2], memory[Address+3]};

// 正确：小端模式
assign Instruction = {memory[Address+3], memory[Address+2],
                     memory[Address+1], memory[Address]};
```

**教训**：
细节决定成败，必须严格按照规范实现。

#### 7.2.2 立即数符号扩展

**问题描述**：
B型指令的立即数拼接顺序错误，导致跳转地址计算错误。

**解决方法**：
仔细查阅RISC-V规范，确认各比特位的位置：
```verilog
// B型立即数：inst[31], inst[7], inst[30:25], inst[11:8], 0
Immediate = {{19{Instruction[31]}}, Instruction[31],
            Instruction[7], Instruction[30:25],
            Instruction[11:8], 1'b0};
```

**教训**：
必须严格遵循指令集规范，不能凭想象设计。

#### 7.2.3 寄存器X0的特殊处理

**问题描述**：
最初忘记X0恒为0的规则，导致X0被错误写入。

**解决方法**：
在寄存器堆模块中添加保护逻辑：
```verilog
// 写操作：禁止写入X0
if (RegWrite && WriteReg != 5'd0) begin
    registers[WriteReg] <= WriteData;
end

// 读操作：强制X0返回0
assign ReadData1 = (ReadReg1 == 5'd0) ? 32'd0 : registers[ReadReg1];
```

**教训**：
需要深入理解指令集的特殊规定。

#### 7.2.4 Vivado仿真配置

**问题描述**：
在Vivado中运行仿真时遇到编译错误和波形显示问题。

**解决方法**：
1. 将`integer`变量声明移到模块级（Vivado要求）
2. 创建专用的Vivado测试平台（移除iverilog特定命令）
3. 正确设置仿真时间单位

**教训**：
不同仿真工具有不同的语法要求，需要针对性适配。
