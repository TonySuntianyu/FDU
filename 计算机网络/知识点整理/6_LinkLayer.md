# 链路层：数据链路层

**链路层（Link Layer）** 负责在通信路径上两个 **物理相邻节点** 之间传输数据报  

*网络层负责在源节点和目的节点之间传输数据报，而链路层负责在物理相邻节点之间传输数据报。*  
*传输层负责在端到端的通信中提供可靠性和流量控制。*  

1. 链路层基本概念与实现
2. 差错检测与纠正 (Error Detection & Correction)
3. 多路访问协议 (Multiple Access Protocols)
4. 局域网技术 (LANs)
5. 链路虚拟化：MPLS

## 1. 概览

### 1.1. terminology（术语）

- nodes：网络中的设备（主机、路由器等）  
- links：连接通信路径上相邻（adjacent）节点的通信渠道（如：有线链路、无线链路、局域网）  
- frames（帧）：链路层的数据单位，负责封装网络层的 IP 数据报。  

### 1.2. 链路层服务

链路层在不同链路上可能提供不同的服务：  

- **成帧与链路访问 (Framing & Link Access)**：  
    将数据报封装成帧，并加上首部（Header）和尾部（Trailer）  
    在共享介质中管理信道访问（MAC 地址用于标识源和目的，与 IP 地址不同）。

- **可靠交付 (Reliable Delivery)**：  
    在相邻节点间保证数据准确，通常用于高误码率的链路（如无线链路）。  

- **流量控制 (Flow Control)**：  
    协调相邻发送和接收节点之间的发送频率。  

- **差错检测与纠正 (Error Detection & Correction)**：  
    检测因信号衰减或噪音产生的比特错误；接收方不仅能检测错误，有时还能在不重传的情况下纠正错误（FEC）。  

- **全双工与半双工 (Full-Duplex & Half-Duplex)**：  
    全双工允许链路两端同时发送，半双工则不允许。  
    半双工同一时间只能有一个方向发送数据（如无线电对讲机）。  

### 1.3. 实现位置

- **网卡 (NIC)**：  
    链路层的功能通常在每个主机的网络适配器或芯片中实现。
- **软硬结合**：  
    它是硬件、软件（驱动程序）与固件（Firmware）的结合体，附着在主机的系统总线上。  

### 1.4. 链路层与网络层的关系

链路层类似于“接力赛”中的具体路段：  
一个数据报从源到目的可能经过多段链路  
每段链路可以使用不同的协议（如第一段用 WiFi，第二段用以太网）  
并提供不同的服务等级。  

## 2. Error Detection & Correction（差错检测与纠正）

链路层中的差错检测与纠正（Error Detection and Correction）  
主要负责处理物理链路传输中产生的比特错误（如 1 变成 0）  

### 2.1. 基本原理

发送方在数据 D 后面添加额外的差错检测与纠正比特 EDC（Error Detection and Correction bits）  
形成帧进行传输  

接收方接收到 D′ 和 EDC′ 后  
通过特定算法判断是否发生比特翻转  

- **冗余性**：  
    差错检测不是 100% 可靠的  
    较大的 EDC 字段能提供更好的检测和纠正能力  

- **权衡**：  
    **纠错（FEC，Forward Error Correction）**相比检测需要更多的冗余位  
    通常在误码率高（如无线链路）或重传代价高（如卫星链路）的情况下使用  

### 2.2. 常见技术与实例分析

#### 2.2.1. 奇偶校验 (Parity Checking)

**单比特奇偶校验**：  
在数据末尾加 1 位，使 1 的总数为奇数或偶数  
只能检测出奇数个比特翻转  
且无法纠正错误  

分为两种类型：  

- **偶校验 (Even Parity)**：使得数据中 1 的总数为偶数  
- **奇校验 (Odd Parity)**：使得数据中 1 的总数为奇数  

**二维奇偶校验 (2D Parity)**：  
将比特排列成矩阵，对每行每列分别计算奇偶校验。
分析实例：  
若发生单比特错误，该位所在的行和列都会出现校验错误  
通过行列交叉点即可定位并纠正该错误  

#### 2.2.2. 因特网校验和 (Internet Checksum)  

- 方法：  
    将数据视为 16 位整数序列进行相加（求反码和），最后取结果的反码。  
    *简单来说，就是把所有 16 位字相加，然后对结果取反码作为校验和。*  
- 特点：  
    计算简单，适合软件实现，但保护能力相对较弱。  
    - 分析实例：  
        如果两个 16 位词中各有一个比特发生翻转，且翻转的位置刚好使它们的和保持不变，校验和将无法检测出该错误  

#### 2.2.3. 循环冗余校验 (Cyclic Redundancy Check, CRC)

CRC 是目前局域网（如以太网、Wi-Fi）中最常用的高效纠错技术  

- 核心逻辑：发送方和接收方预先商定一个 r+1 位的生成多项式 G。
- 计算步骤：
    1. 发送方将 d 位数据后面补 r 个 0。
    2. 使用模 2 运算（异或操作）进行长除法，计算数据被 G 除得的余数 R。
    3. 发送 d+r 位内容，确保该内容能被 G 整除。
- 实例分析：  
    若数据 D=101110，生成多项式 G=1101（r=3）  
    发送方在 D 后加三个 0 并除以 1101  
    得到的余数 R（如 011）拼接在数据后发送  
    接收方若除得余数为 0 则认为无误  

## 3. 多路访问协议（Multiple Access Protocols）

### 3.1. 概念与术语(Concepts & Terminology)

多路访问协议（Multiple Access Protocols）  
是一种定义了多个节点如何共享、争用同一个物理通信信道的一套规则  

Collision（冲突，碰撞）  
指两个或多个节点同时尝试发送数据，导致信道上的数据包相互干扰。  

Multiple Access Channel（多路访问信道，MAC）  

### 3.2. 设计目标

多路访问协议的主要任务是：  

1. 分配信道资源：  
    决定哪个设备在什么时候可以使用信道。
2. 避免碰撞：  
    尽量防止两个设备同时发送数据。
3. 处理冲突：  
    如果碰撞已经发生，决定如何检测并重新发送。

理想准则：  
给定一个MAC，信道速率 R 和 M 个竞争节点  

1. 全速传输 (Full Rate)：当只有一个节点发送数据时，该节点可以以全部信道速率 R 传输数据。
2. 公平分享 (Fairness)：当有 M 个节点同时竞争发送数据时，每个节点平均获得的吞吐量应为 R/M。
3. 完全去中心化 (Fully Decentralized)：
    - 不需要专门的主节点来协调传输。
    - 不需要全局的时钟或时隙（Slots）同步。
4. 简单性 (Simple)：协议的实现应当尽可能简单。

### 3.3. 协议分类

Taxonomy（分类）  
多路访问协议主要分为三大类：

- 信道划分协议 (Channel Partitioning)：  
    Channelization  
    将信道资源划分为小块（时间片、频率），分配给节点独占
- 随机接入协议 (Random Access)：  
    信道不划分，允许冲突发生，并规定如何从冲突中恢复
- 轮流协议 ("Taking Turns")：  
    Controlled Access  
    节点轮流发送数据，通常允许需求大的节点占用更多时间  

### 3.4. 信道划分协议 (Channel Partitioning)  

主要机制：  

- **TDMA（时分多址接入）**：将时间划分为多个时隙，每个节点在特定时隙内发送数据。  
- **FDMA（频分多址接入）**：将信道划分为多个频段，每个节点使用特定频段进行通信。  

#### 3.4.1. TDMA（时分多址接入）

时间->周期性的Rounds(轮)  
Round->固定数量的时隙(Slots)  

**运行机制**  
每个节点在每一轮中被分配一个特定的、固定长度的时隙。节点只能在其专属时隙内发送数据  

**实例分析**  
假设一个 LAN 有 6 个站点，只有 1、3、4 号站点有数据。在 TDMA 下，2、5、6 号时隙在每一轮中都会处于空闲状态（Idle），这些带宽资源无法被其他有需求的站点抢占，导致了资源的浪费。  

#### 3.4.2. FDMA（频分多址接入）

Channel总频谱->若干个固定带宽的频带(Frequency Bands)  

**运行机制**  
每个站点被分配一个专属频带，可以连续地在该频率下传输。  
与 TDMA 类似，它为每个节点提供了独占的通信管道。  

**缺点分析**  
即便站点在大部分时间内不发送数据，该频带依然被其占用。  
对于计算机通信这种“突发性”（Bursty）极强的流量（即长时间静默，短时间爆发），FDMA 会造成极大的资源闲置。  

#### 3.4.3. 性能评价与适用场景

- 高负载（High Load）：  
    信道划分非常高效且公平。因为它消除了节点间的冲突，确保每个节点都能获得稳定的平均带宽。

- 低负载（Low Load）：  
    效率非常低。节点必须等待其专属时隙，且即便信道完全空闲，单个活跃节点也只能使用其分到的 1/N 带宽。

- 核心权衡：  
    这种预先分配（Dedicated Allocation）的机制虽然保证了服务的确定性，但牺牲了共享信道的灵活性。  

### 3.5. 随机接入协议 (Random Access)

**核心特征**  
是节点在发送数据前 **不进行预先协调** ，且发送时占用整个信道带宽 R。  
当两个或多个节点同时发送时会产生碰撞（Collision）  
协议规定了如何 **检测** 并从碰撞中 **恢复**  

#### 3.5.1. ALOHA 协议系列

- Pure ALOHA（纯ALOHA）  
    简单，无需时钟同步。节点有数据即刻发送，碰撞概率更高。
    - 效率：最大效率仅为 18%。
- Slotted ALOHA（时隙ALOHA）  
    将时间划分为等长的时隙，节点仅在时隙开始时发送。  
    若发生碰撞，节点以概率 p 在后续时隙重传。
    - 效率：最大效率约为 37%。

#### 3.5.2. CSMA 协议系列

CSMA（Carrier Sense Multiple Access，载波监听多路访问）  

**基本原则**  
“发送前先监听”：若信道空闲则发送完整帧，若忙则推迟发送  

*依然有碰撞*  
**碰撞成因**  
由于传播时延（Propagation Delay）  
节点 A 开始发送后，信号尚未到达节点 B，导致 B 误以为信道空闲也开始发送，从而引发碰撞  

##### 3.5.2.1. CSMA/CD（带碰撞检测的载波监听多路访问）

CD（Collision Detection，碰撞检测）  
主要用于有线以太网  
节点在发送的同时进行监听，一旦检测到碰撞立即停止发送，以减少信道浪费  

二进制指数退避算法：碰撞后，节点从 ${0,1,…,2^m −1}$ 中随机选一个 $K$，等待 $K \times 512$ 比特时间再重试  

实例分析：以太网碰撞最差情况

- 场景：主机 A 和 B 位于 2500 米长链路的两端，传播时延为 d。
- 分析：  
    若 A 在 t 时刻发送，其信号在 t+d 时刻到达 B。  
    若 B 在信号到达前一瞬开始发送，则 B 立即检测到碰撞并停止  
    但 A 需等到 t+2d 时刻才能收到 B 的信号并发现碰撞  
    因此，以太网帧必须足够长（至少 512 bit），以确保发送方在完成发送前能监听到所有可能的碰撞。

##### 3.5.2.2. CSMA/CA（碰撞避免）

CA（Collision Avoidance，碰撞避免）  

主要用于 802.11 无线网络。  
由于无线环境下无法实现可靠的碰撞检测（自身发射功率远大于接收功率）  
协议采用显式确认（ACK）机制。  

- 隐蔽站问题（Hidden Node Problem）：节点 A 和 C 都能联系到 B，但 A 和 C 彼此听不到。
- 实例分析：RTS-CTS 握手
    - 分析：发送方先发一个短的 RTS（请求发送）包，接收方回以 CTS（清除发送）包。CTS 包能被其范围内所有节点（包括隐蔽站）听到，从而通知它们在指定时间内保持静默，避免了 A 和 C 在 B 处产生信号碰撞。

### 3.6. 轮流协议 ("Taking Turns")

又被称为**受控访问协议（Controlled Access Protocols）**。  

**设计动机**  
结合信道划分协议（高负载下公平高效）和随机接入协议（低负载下延迟低）的优点，力求实现“两全其美”

核心机制：  

- **Polling（轮询）**  
- **Token Passing（令牌传递）**
- **Grants（集中式授权）**

#### 3.6.1. Polling（轮询）

在这种模式下，指定一个主节点（Master）  
由它循环“邀请”其他从节点（Slaves）传输数据

- 运行机制：  
    主节点向节点发送轮询消息，节点若有数据则发送，发送完或无数据则反馈给主节点，主节点再轮询下一个。
- 优缺点：  
    消除了碰撞和冲突浪费  
    但引入了轮询开销（等待消息的时间）和单点故障风险（主节点挂了则全网瘫痪）。
- 实例分析：  
    **蓝牙 (Bluetooth)**  
    蓝牙主设备将时间划分为 625 µs 的时隙，只有主设备能在奇数时隙发起传输，从设备仅在收到主设备请求后的下一个偶数时隙才能响应，这彻底避免了从设备间的竞争。

#### 3.6.2. Token Passing（令牌传递）

一种去中心化的轮流机制，通过一个特殊的控制帧—— **令牌 (Token)** 在节点间按固定顺序循环传递  

- 运行机制：  
    节点只有在抓取到令牌时才有权发送数据。  
    发送完毕或没有数据时，必须将令牌传递给逻辑上的下一个节点。
- 优缺点：  
    非常公平，节点按需占用信道  
    但在令牌丢失或某个节点关机导致环路断开时，需要复杂的维护协议来重新生成令牌。
- 实例分析：  
    令牌环 (Token Ring/IEEE 802.5)  
    节点物理或逻辑成环。当一个节点想发数据且看到令牌流过时，它会截留令牌并插入数据帧；数据绕环一周被接收方复制，最后回到发送方被清除，发送方随后释放令牌以供下游使用。

### 3.7. GSM（Global System for Mobile Communications，全球移动通信系统）

GSM（全球移动通信系统）的空中接口是链路层多路访问协议的一个综合实例，它巧妙地结合了信道划分（FDM/TDM）和随机接入技术，以支持大规模用户的语音和数据需求。  

- 频分多路复用 (FDM)：系统将分配的无线电频谱划分为多个 **载波（Carriers）** 或频率带。例如，在典型的配置中包含 4 个载波。
- 时分多路复用 (TDM)：在每一个频率载波上，时间被进一步划分为重复的帧。每一帧包含 8 个固定的时间片（Time Slots）  

GSM 根据功能将这些时隙定义为不同类型的逻辑信道：

- 公共控制信道 (Common CCH)：位于第一载波的第一个时隙（Slot 0）。
    - 分析：这是所有移动设备接入网络的入口。所有用户在请求连接时，会通过 **随机接入（Random Access）** 的方式竞争此信道的使用权。
- 独立专用控制信道 (SDCCH)：位于第一载波的第二个时隙（Slot 1）。
    - 分析：该时隙被预留用于处理连接建立过程中的信令交换。
- 业务信道 (TCH)：跨越所有载波的其他时隙均被指定为业务信道，专门用于传输语音数据。

## 4. 局域网技术 (LANs)

局域网（Local Area Networks，LANs）  
连接近距离节点（通常小于 1 km）的网络技术  
其核心涵盖了从物理拓扑、链路寻址到虚拟化隔离的多个维度  

### 4.1. Addressing（寻址）与ARP（Address Resolution Protocol，地址解析协议）

网络中的寻址（Addressing）和地址解析协议（ARP）是实现端到端通信的关键机制  

之前网络层使用 IP 地址进行寻址  
根据CIDR（无类别域间路由选择）划分子网  
提升了路由效率  

链路层寻址：  
**MAC 地址 (MAC Addressing)**  
（MAC，Media Access Control，介质访问控制）  

#### 4.1.1. MAC Address（介质访问控制地址）

**性质**：  
MAC 地址是 48 位的平面地址（Flat address）  
通常固化在网卡（NIC）的 ROM 中，具有全球唯一性  

**作用**：  
它仅在“本地”起作用，负责在同一个子网内的相邻接口之间移动帧。

**类比**：  
MAC 地址类似于身份证号（永久且无结构）  
而 IP 地址类似于邮寄地址（随位置变化且具有层级）  

#### 4.1.2. ARP（地址解析协议）

从 IP 到 MAC 的桥梁  

**功能**：  
当主机知道目的地的 IP 地址时，ARP 用于解析出对应的 48 位 MAC 地址，以便封装链路层帧。  

**运行机制**：  

1. 查询 ARP 表：每个节点维护一个 ARP 缓存表，存储 \<IP; MAC; TTL\> 映射。
2. 广播请求：如果表中没有目标映射，发送方会发送一个 ARP 查询帧，目的地 MAC 地址设为广播地址（FF-FF-FF-FF-FF-FF）。
3. 单播响应：子网内匹配该 IP 的节点会以单播方式向请求者发送包含自己 MAC 地址的 ARP 响应帧。
4. 更新缓存：请求方收到响应后更新本地 ARP 表。  

#### 4.1.3. 实例分析：跨子网路由 (Routing between subnets)

假设主机 A 跨越路由器 R 向主机 B 发送数据：

1. A 生成 IP 数据报：源 IP 为 A，目的 IP 为 B。
2. A 封装链路层帧：由于 B 不在同一个子网，A 通过 ARP 获取默认网关 R 的 MAC 地址。此时帧的源 MAC 是 A，目的 MAC 是 R。
3. R 处理数据报：路由器 R 拆除链路层头部，根据目的 IP 查路由表，确定输出接口。
4. R 重新封装帧：R 通过 ARP 获取 B 的 MAC 地址。此时新帧的源 MAC 是 R，目的 MAC 是 B。注意：整个过程中 IP 首部保持不变，但 MAC 首部在每一跳都会重写。

IP 地址决定了数据的最终目的地，而 MAC 地址则负责将数据“接力”传递给下一跳物理邻居

### 4.2. 以太网 (Ethernet)

以太网（Ethernet）是目前最占统治地位的有线局域网技术  
核心特点是造价低廉、性能稳健且易于管理  

#### 4.2.1. 核心服务与特征

- 无连接与不可靠：  
    以太网在发送方和接收方 NIC 之间没有握手过程（无连接），且接收方不发送确认（ACK）或否定确认（NAK）。  
    如果帧未通过 CRC 校验，则直接丢弃，可靠性由高层协议（如 TCP）负责。
- 物理拓扑演进：  
    从早期的总线型（所有节点在同一个冲突域内）演变为现代的交换型（使用交换机，各链路互不干扰，支持全双工）。

#### 4.2.2. 以太网帧结构

- 前导码 (Preamble, 8字节)：  
    前7字节为 10101010，最后1字节为 10101011，用于同步发送方与接收方的时钟频率。
- MAC 地址 (各6字节)：  
    包含源地址和目的地址。  
    如果 NIC 收到匹配自己 MAC 或广播地址的帧，则上传给网络层，否则丢弃。
- 类型 (Type)：  
    标识高层协议（通常是 IP），用于多路分解。
- 数据 (Payload)：  
    46 到 1500 字节。如果数据小于 46 字节，则必须填充到 46 字节。
- CRC (4字节)：  
    循环冗余校验，用于检测比特错误，检测到错误即丢帧。

#### 4.2.3. 介质访问控制：CSMA/CD

采用 CSMA/CD 协议管理共享信道访问  
通过碰撞检测和二进制指数退避算法提高信道利用率  

### 4.3. Switches（交换机）

以太网交换机（Ethernet Switch，历史上也称网桥 Bridge）  
是软件定义网络（SDN）数据平面的基础硬件  
也是局域网的核心连接设备  

#### 4.3.1. 核心功能与特性

- 层次与职责：  
    交换机是数据链路层（L2）设备，负责在物理相邻节点间存储并转发以太网帧。
- 透明与即插即用：  
    主机无法察觉交换机的存在；交换机无需人工配置，接入即可工作，具备“自学习”能力。
- 多路并发：  
    与早期的集线器（Hub）不同，交换机支持全双工通信。  
    它允许多对主机（如 A 传给 A'，B 传给 B'）在互不冲突的情况下同时传输数据，每个端口都是一个独立的冲突域。  

#### 4.3.2. 运行机制：自学习与交换表

交换机通过构建 **交换表（Switch Table）** 来实现智能转发  
表中每一项包含：(MAC 地址, 接口, 时间戳)。

- 自学习过程：  
    当交换机从某个接口收到一个帧时，它会提取该帧的源 MAC 地址并记录对应的入端口。  
    如果表中已存在该地址，则更新其生存时间（TTL）。
- 老化机制：  
    表项在 TTL 到期（如 120 秒）后会被自动删除，以适应主机移动或网卡更换的情况。

#### 4.3.3. 转发逻辑（匹配 + 动作）

当一个帧到达入端口时，交换机执行以下逻辑：

1. 记录：根据源地址执行自学习，更新交换表。
2. 检索：在表中查找该帧的目的 MAC 地址。
3. 决策：
    - 命中且在同侧：若目的地址对应的端口就是入端口，则丢弃该帧（无需转发）。
    - 命中且在异侧：将帧定向转发到对应输出端口。
    - 未命中：执行“泛洪”（Flood），将帧转发给除入端口外所有活跃端口。

#### 4.3.4. 实例分析：自学习过程

场景描述：  
交换机有接口 1, 2, 3, 4。  
主机 A 连在接口 1，主机 A' 连在接口 4。初始交换表为空。

- 步骤 1：A 发送帧给 A'
    - 分析：交换机收到帧，记录 (A, 1, TTL) 到交换表。由于表中没有 A'，交换机向接口 2, 3, 4 泛洪。
- 步骤 2：A' 收到后回复 A
    - 分析：交换机在接口 4 收到回复帧，记录 (A', 4, TTL)。此时检索表发现 A 已经在接口 1，于是直接将帧从接口 1 发出。
- 结果：此后 A 与 A' 之间的通信将全部是定向转发，不再产生多余的广播流量。

#### 4.3.5. 局限性与扩展技术

- 环路问题：  
    如果网络物理连接存在环路，泛洪会导致帧在网络中无限循环。  
    此时需要运行生成树协议（STP），通过逻辑上关闭某些端口将拓扑简化为无环的树。
- 广播风暴：  
    L2 网络无法阻挡广播帧（如 ARP），当网络规模过大时会严重消耗带宽。  
    为此引入了 VLAN（虚拟局域网），通过软件手段将一个物理交换机分割成多个逻辑隔离的广播域。

### 4.4. 虚拟局域网 (VLANs)

**虚拟局域网（VLANs）** 是一种在单一物理网络基础设施上定义多个逻辑局域网的技术  
旨在解决传统局域网扩展性差和管理困难的问题  

#### 4.4.1. 核心背景与动机

在传统的单一广播域中，所有二层广播流量（如 ARP 请求、DHCP 等）都会传遍整个网络，这会导致以下问题：

- 扩展性差：随着主机数量增加，广播风暴会消耗大量带宽。
- 安全性低：同一个局域网内的用户可以轻易监听彼此的流量。
- 缺乏灵活性：如果一个用户物理搬迁到了另一个楼层，通常需要重新布线才能保持在原有的子网中。

#### 4.4.2. 基于端口的 VLAN（Port-based VLAN）

这是最常见的实现方式，通过交换机管理软件将物理端口划分为不同的逻辑组：

- 流量隔离：  
    属于 VLAN 100 的端口发出的帧只能到达同属于 VLAN 100 的端口。
- 动态管理：  
    管理员可以随时通过软件更改端口所属的 VLAN，而无需移动物理线缆。  

#### 4.4.3. 跨交换机扩展与 802.1Q 协议

当 VLAN 需要跨越多个交换机时，需要使用**中继端口（Trunk Port）**：

- Trunk 端口：
    负责在交换机之间传输携带 VLAN 标记的帧。
- 802.1Q 帧格式：  
    在原始以太网帧中插入一个 32 位的标签。其中包含 12 位的 VLAN ID（支持 4096 个 VLAN）和 3 位的优先级字段。  
    - VLAN ID：标识该帧所属的 VLAN。  
    - 优先级字段：用于实现服务质量（QoS）策略。

#### 4.4.4. 实例分析：跨部门办公搬迁

场景描述：某大学有计算机系（CS）和电子工程系（EE）两个 VLAN。一名 CS 系的教职工将其办公室搬迁到了物理上连接 EE 交换机的区域。

- 传统方式：必须将该教职工的电脑接入 CS 的物理交换机，或者在 EE 交换机上进行复杂的重布线。
- VLAN 方案：管理员只需在 EE 所在交换机上，将该用户连接的端口（例如端口 4）从 EE VLAN 动态重新分配到 CS VLAN 即可。
- 分析结论：虽然该用户在物理位置上被 EE 系包围，但其逻辑流量仍属于 CS VLAN，实现了逻辑拓扑与物理位置的解耦

梳理总结：  
VLAN 通过逻辑划分提升了效率与安全。但在超大规模云数据中心，由于 4096 个 ID 的限制，目前正逐渐向支持 1600 万个 ID 的 VXLAN 技术演进。  

## 5. 链路虚拟化：MPLS（Multi-Protocol Label Switching，多协议标签交换）

**多协议标签交换（MPLS）** 是一种将 **虚电路（Virtual Circuit）** 的交换思想与 **数据报（Datagram）**的灵活性相结合的技术  
通常被认为运行在数据链路层和网络层之间（即 **Layer 2.5**）  

### 5.1. 核心动机与目标

MPLS 的主要目标是利用固定长度的标签（Label）来实现高速的 IP 转发  
从而代替网络层中较为复杂的最长前缀匹配（Longest Prefix Matching）查找算法。  
此外，它还能提供传统 IP 路由难以实现的流量管理功能。  

### 5.2. 核心架构与关键设备

在 MPLS 网络中，路由器根据功能分为两类：

- **LSR (Label Switched Router)**：  
    标签交换路由器。它仅根据数据包头部的标签值进行转发，不检查其内部的 IP 地址。
- **LER (Label Edge Router)**：  
    标签边缘路由器。位于 MPLS 网络的边缘，负责在进入 MPLS 网络时为数据包分配标签（入标签）以及在离开 MPLS 网络时移除标签（出标签）。  

### 5.3. MPLS 标签与头部结构

MPLS 头部通常作为一个“垫层”（Shim）插入在二层头部和三层头部之间。其结构包含：

- Label (20位)：用于标识路径的标签，具有链路本地范围（即同一标签在不同链路上意义可以不同）。
- Exp (3位)：试验位，常用于流量分类或优先级处理。
- S (1位)：栈底位，标识是否还存在嵌套的其他标签。
- TTL (8位)：生存时间，防止环路。

### 5.4. 转发机制：FEC 与 标签交换

MPLS 引入了 **转发等价类（FEC）** 的概念  
即一组在路由器中获得相同处理的分组集合（例如匹配同一前缀的所有分组）。

- 运行机制：入口 LER 确定分组所属的 FEC 并加上标签。后续 LSR 维护一个标签转发表（包含入标签、出标签、目的地和出接口）。
- 信令协议：使用 RSVP-TE 等协议在下游路由器中建立转发项，或通过修改后的 OSPF/IS-IS 泛洪链路带宽及预留信息。

### 5.5. 实例分析：MPLS 与传统 IP 路由的路径对比

场景描述：假设网络中有一条从源 U 到目的地 Z 的路径，存在多条物理链路。

- 传统 IP 路由分析：路径完全由目的 IP 地址决定。如果 U 到 Z 的最短路径只有一条，所有流量都会拥挤在此链路上，难以实现负载均衡或绕过特定链路。  

- MPLS 转发分析：
    - 流量工程 (Traffic Engineering)：LER 可以根据源地址或其他字段将 U 到 Z 的流量划分到不同的标签路径上（如一部分走 uvwz，另一部分走 uxyz），实现负载均衡。
    - 快速重路由 (Fast Reroute)：MPLS 可以预先计算备份路径。一旦某条链路失效，路由器可以立即切换标签指向备份路径，无需等待全局路由协议重新收敛。

### 5.6. MPLS 的应用场景

- VPN 隧道（Virtual Private Network Tunnel）：  
    MPLS 头部可以看作一个只有 4 字节的隧道头部，非常适合构建二层 VPN（透传以太网帧/ATM元胞）或三层 VPN（隔离不同客户的地址空间）。
- 异构网络集成：  
    它允许在不支持原生 IP 转发的硬件（如 ATM 交换机或光交换机）上运行 IP 控制协议，从而实现 Generalized MPLS (GMPLS)。

ATM（Asynchronous Transfer Mode，异步传输模式）
