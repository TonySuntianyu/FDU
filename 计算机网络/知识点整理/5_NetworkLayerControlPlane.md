# 网络层：控制平面

**网络层控制平面（Control Plane）**  
核心任务是决定分组从源到目的地的端到端路径  
即执行“路由选择（Routing）”功能

## 1. 概览

### 1.1. 核心目标

控制平面的核心任务是理解网络层服务的原理，包括传统路由算法、SDN 控制器、网络管理以及具体的互联网实现（如 OSPF、BGP、ICMP）  

### 1.2. Forwarding vs. Routing

- 转发 (Forwarding)：  
    属于数据平面，是路由器的局部功能。它负责将分组从路由器的输入端口移动到合适的输出端口  
- 路由 (Routing)：
    属于控制平面，是网络范围的逻辑。它负责确定分组从源主机到目的主机跨越网络所采取的完整路径  

### 1.3. Structuring Control Plane

构建控制平面的两种方法：  

1. **每路由器控制（Traditional Per-router Control）**  
    每台路由器内部都有一个路由算法组件，它们在控制平面中相互交互，独立计算并填充本地转发表  
2. **逻辑集中式控制 (SDN Approach)**  
    采用软件定义网络（SDN）模式，由远程服务器（控制器）集中计算并下发流表到交换机中，实现了控制平面与数据平面的解耦  

### 1.4. 为何推行SDN？

- 简化管理：避免了繁琐的路由器逐台配置，增强了流量引导的灵活性
- 可编程性：通过流表和 API（如 OpenFlow）实现对网络行为的编程控制
- 开放性：打破了厂商对控制平面的软硬件垂直集成垄断，促进了网络创新

## 2. Routing Algorithms

路由选择协议的目标是寻找“好”的路径，通常指代价最低、速度最快或拥塞程度最低的路径  
而算法则是实现这些协议的具体方法  

基础概念：  

- **路径（Path）**：  
    从源节点到目的节点的路由器序列  
- **链路代价（Link Cost/Metric）**：  
    网络结构基于图的抽象  
    link cost作为图中边的权重  
    $C_{a,b}$ 描述从a到b的直接链路的开销（没有直接链路就是无穷大）  
    由网络管理员定义，可以总为1（代表hop count），也可以基于带宽、延迟等动态因素，甚至反过来基于拥塞程度定义（拥塞越大，代价越高）  

路由选择算法主要分为两类：  

- **链路状态算法 (Link State, LS)**  
- **距离向量算法 (Distance Vector, DV)**  

### 2.1. 链路状态算法 (Link State, LS)

**特点**  
具有全局性。所有路由器都掌握完整的网络拓扑和链路代价信息，这通过“链路状态广播”实现  

#### 2.1.1. 核心算法

**Dijkstra 最短路径算法**  

- 过程：  
    算法是迭代的，每次选择当前已知的最短路径节点，更新其邻居节点的路径信息，直到所有节点都被处理完毕  
    经过k次迭代后，可以确定k个最近目的节点的最短路径  
- 复杂度：  
    对于n个节点，算法复杂度 $O(n^2)$  
    可能可以优化至 $O(n \log n)$  
    此外需要考虑消息复杂度（每个router必须向其他n个routers广播他的link state info）  
    如果通过高效广播，单次广播：$O(n)$ 链路穿透 (Link Crossings)  
    总消息复杂度：$O(n^2)$ 链路穿透  
- 局限性：  
    如果链路代价取决于流量，可能会产生路由震荡现象  
    *具体解释：当网络流量变化时，链路的代价也会随之变化，这可能导致原本最优的路径变得次优，从而引发路由器不断更新其路由表，形成震荡。*  

#### 2.1.2. 具体迭代示例

Notation：  

- $C_{x,y}$：节点x到节点y的链路开销，如果不是直接相连则为无穷大  
- $D(v)$：从源节点到节点v的当前已知最短路径开销  
- $p(v)$：从源节点到节点v的当前已知最短路径上的前驱节点  
- $N'$：当前已知的所有目的节点集合  

初始化：  

1. $N' = \{u\}$  
2. 对于每个节点v：  
   - 如果v与u直接相连，则 $D(v) = C_{u,v}$，$p(v) = u$  
   - 否则，$D(v) = \infty$，$p(v) = \text{NIL}$  

迭代步骤：  

1. 从 $N - N'$ 中选择一个节点w，使得 $D(w)$ 最小  
2. 将w加入 $N'$  
3. 对于每个节点v不在 $N'$ 中：  
    - 如果 $D(w) + C_{w,v} < D(v)$，则更新：  
        - $D(v) = D(w) + C_{w,v}$  
        - $p(v) = w$  
    - 否则，保持不变  
4. 重复步骤1-3，直到所有节点都在 $N'$ 中  

具体计算示例可见（课件5 P22）  

### 2.2. 距离向量算法 (Distance Vector, DV)

**特点**  
分布式、异步迭代  
每个节点仅与直接相邻的邻居交换开销估计信息  

#### 2.2.1. 核心算法

**Bellman-Ford 最短路径算法**  

**核心方程**  
$$
D_x(y) = \min_{v} \{c(x,v) + D_v(y)\}
$$

- 解析：  
    - $D_x(y)$：节点x到节点y的当前估计开销  
    - $c(x,v)$：节点x到其邻居v的链路开销  
    - $D_v(y)$：邻居v到节点y的估计开销  
    - 该方程表示节点x通过其邻居v到达节点y的最小开销  
- 过程：  
    节点维护到所有目的地的距离向量  
    当收到邻居的更新或者本地链路的代价变化时  
    重新计算向量并通知邻居  

具体计算示例可见（课件5 P35）  

#### 2.2.2. 问题

存在“**无穷计数问题（Counting to Infinity）**”  
即“好消息传得快，坏消息传得慢”  

解释：  

- 无穷计数：  
    当一条链路失败时，节点可能会错误地认为通过邻居仍然可以到达目的地，导致开销不断增加，最终趋向无穷大  
    案例：  
    假设路径为 $A-B-C$，链路代价均为 1。  
    正常情况下，$B$ 知道去 $C$ 的代价是 1，$A$ 知道去 $C$ 的代价是 2。  
    突然，$B$ 到 $C$ 的链路断了。  
    $B$ 发现断了，但此时它收到 $A$ 发来的向量：“我去 $C$ 的代价是 2 哦”。  
    $B$ 心想：“既然我直接去不了 $C$，那我可以绕道 $A$ 呀！”  
    于是 $B$ 更新去 $C$ 的代价为 $2 + 1 = 3$。  
    $A$ 收到 $B$ 的更新，又把自己的代价更新为 $3 + 1 = 4$。  
    结果：  
    两个路由器互相欺骗，代价不断往上涨，直到涨到协议规定的“无穷大”（RIP 中是 16）才会停止。  
- “好消息”  
    当链路恢复时，节点可以迅速更新其路由信息，传播新的最短路径  
- “坏消息”  
    当链路失败时，节点需要通过邻居逐步更新其路由信息，传播失败信息的速度较慢  

#### 2.2.3. 优化方案

**水平分割（Horizontal Partitioning）**  
通过将网络划分为多个区域（Area），每个区域内部使用链路状态协议，区域之间使用距离向量协议，从而减少路由信息的传播范围，提高收敛速度。  
形象来说达成效果：如果 B 知道去 C 的路是 A 告诉他的，B 就不再向 A 宣告这条路径，从而避免了循环路径的形成。  

**毒性逆转（Poison Reverse）**  
当节点通过某个邻居学习到一条路径时，如果该路径的开销变为无穷大，节点会立即通知该邻居这条路径的开销为无穷大，从而防止邻居继续使用这条路径。  
形象描述：当 B 通过 A 学到去 C 的路径时，如果 B 发现这条路径不可达，它会告诉 A：“嘿，我去 C 的路现在是无穷大哦！”这样 A 就不会再把这条路径告诉 B 了。  

### 2.3. 两种算法对比

| 特性       | Dijkstra (Link-State)              | Bellman-Ford (Distance Vector) |
| ---------- | ---------------------------------- | ------------------------------ |
| 拓扑知识   | 掌握全网地图                       | 只知道邻居信息（“听风就是雨”） |
| 计算位置   | 每台路由器独立计算                 | 分布式、迭代计算               |
| 消息复杂度 | n routers-> $O(n^2)$ messages sent | 只在邻居之间交换，收敛速度不定 |
| 收敛速度   | 快                                 | 慢（且可能有环路）             |
| 鲁棒性     | 较强，一个节点出错影响有限         | 较弱，错误信息会全网扩散       |
| 代表协议   | “OSPF, IS-IS”                      | “RIP, BGP (路径向量变体)”      |

## 3. Routing Protocols

### 3.1. 路由协议的意义

在Routing Algorithms中，我们所讨论的网络结构都是很理想的  

- 所有的routers都是相同的  
- 网络是扁平的  

但实际上，互联网是非常复杂的  

主要问题：  

**Scale（规模巨大）**  
billions of destination hosts  
这不可能全部存在于每个router的routing table中  
且路由器之间的信息交换就可能直接淹没链路  

**Administrative Autonomy（管理自治）**  
Internet实际上是“网络的网络”，处于非常高的层次  
每个网络的admin都希望可以对自己的网络的路由拥有控制权  

### 3.2. AS（自治系统）

那么Internet通过什么方法实现网络的可扩展性呢？  
采用了 **分层路由模式**  

简单来说就是将routers聚合至不同的区域  
被称为“**自治系统（Autonomous Systems, AS）**”  
也称为“域（Domain）”  

那么处理方法也分为两类：  

- **intra-AS**/domain  
    `intra-`表示“内部的”  
    同AS下的routers之间的路由选择协议  
    - 同AS下的routers必须运行相同的intra-domain protocol  
    - 不同的AS下的routers则可以不同  
    - **gateway router（网关路由器）**：在其AS的边界上，有到其他AS的路由器的链路连接  
- **inter-AS**/domain  
    `inter-`表示“之间的”  
    不同AS之间的路由选择协议  
    - gateways负责进行inter-domain routing  

常见Intra-AS routing protocols：  

- RIP（Routing Information Protocol）  
    传统DV  
    基本不再广泛使用  
- EIGRP（Enhanced Interior Gateway Routing Protocol）  
    Cisco曾经专有的混合协议（2013年后开放）  
    DV based  
- OSPF（Open Shortest Path First）  
    LS routing  
    IS-IS protocol 基本类似（IS-IS，Intermediate System to Intermediate System）

### 3.3. intra-ISP routing: OSPF

OSPF（Open Shortest Path First）是一种链路状态路由协议，互联网中最常用的域内路由协议。  

#### 3.3.1. 基本属性

**开放性**  
OSPF为公开非专有标准，由IETF定义  

**链路状态协议（Link-State Protocol）**  
经典的LS协议  
每个路由器掌握整个所属的AS的完整拓扑信息  

**传输机制**  
OSPF Daragram直接封装在IP Datagram中  
不使用TCP或UDP  

#### 3.3.2. 工作原理

**泛洪通告**  
LSA（Link-State Advertisement）  
每台router向AS内所有其他routers泛洪LSA  
描述其直接链路的代价和状态  

**拓扑同步**  
通过泛洪，所有的节点最终会拥有相同的链路状态数据库（Link-State Database, LSDB）  
也就是网络地图  

**最短路径计算**  
每台router本地运算Dijkstra算法  
计算以自身为root的最短路径树  
从而生成其转发表  

#### 3.3.3. 层次化结构

为了提高在大规模网络中的可拓展性  
OSPF也支持层次化结构  
即将一个AS划分为多个 **区域（Area）**  

**主干区域（Backbone Area）**  
区域0，负责汇总并分发来自其他区域的路由信息  

**ABR（Area Border Router）**  
同时连接本区域和主干区域的路由器  
负责将Area内的路径成本汇总并通告给主干区域  

**ASBR（Autonomous System Boundary Router）**  
连接到其他AS的路由器

#### 3.3.4. 关键特性

**安全性**  
所有的OSPF Daragram都经过Authentication  
防止恶意注入错误信息  

**多路负载均衡（Load Balancing）**  
当到达同意目的地存在多条等价路径时  
OSPF可以实现流量在这些路径上的均衡分配  

**多指标支持**  
Link Cost可以基于带宽、时延等多种度量指标进行配置  

### 3.4. inter-ISP routing: BGP

BGP（边界网关协议）是互联网自治系统间（Inter-AS）路由选择的唯一标准协议，被称为“将互联网连接在一起的胶水”  

#### 3.4.1. 基本角色和会话类型

BGP 允许子网向互联网其余部分通告其存在，并获取到达外部网络的可达性信息  

有两种类型的BGP：  

- **eBGP（Exterior BGP，外部BGP）**  
    运行在不同AS之间的网关路由器之间  
    用于从相邻 AS 获取子网可达性信息  
- **iBGP（Interior BGP，内部BGP）**  
    运行在同一AS内的网关路由器之间  
    用于在 AS 内部所有路由器之间传播这些可达性信息  

运行机制：  
两个BGP路由器（peer-routers）之间通过半永久性的 TCP 连接交换 BGP 报文  
*BGP是一种路径向量（Path Vector）协议*  
*不仅通告目的地，还通告到达目的地所经过的完整 AS 路径*  

#### 3.4.2. BGP Messages（BGP报文类型）

BGP Messages运行在TCP之上  
主要包含4种类型的报文：  

- **OPEN**  
    用于开启与对等方的 TCP 连接并对发送方进行身份验证  
- **UPDATE（critical！）**  
    最为关键，用于通告一条新的路径信息，或者撤销（Withdraw）之前通告过的失效路径  
- **KEEPALIVE**  
    在没有 UPDATE 报文时保持连接存活，同时也作为对 OPEN 请求的确认  
- **NOTIFICATION**  
    用于报告报文错误或关闭连接  

#### 3.4.3. 路径属性与路由 (Path Attributes and Routes)

BGP route：  
Prefix + Path Attributes 的组合  

**关键属性**  

- **AS-PATH**  
    记录了route advertisement经过的所有AS序列  
    如果router在其中发现自己的AS编号，则丢弃该route advertisement，防止路由环路  
- **NEXT-HOP**  
    指示下一跳AS的具体内部路由器IP地址  

**Policy-based Routing（政策驱动的路由选择）**  
BGP的route选择高度依赖于AS Admin的 **Policy（政策）**  
routers根据“导入政策”决定是否接收某条Path  
根据“导出政策”决定是否向邻居通告某条Path  

#### 3.4.4. BGP Path Advertisement（BGP路径通告）

示例：（课件5 P60）  

1. 假设 AS3 包含前缀 X。  
2. AS3 的网关路由器 3a 通过 eBGP 向 AS2 的路由器 2c 通告路径“AS3, X”。  
3. 路由器 2c 接收后，通过 iBGP 将此路径告知 AS2 内部所有路由器。  
4. 随后，AS2 的网关 2a 可能根据自身政策，向 AS1 的网关 1c 通告路径“AS2, AS3, X”  

错误检测：  
如果路由器在接收到的 AS-PATH 中发现自己的 AS 号，则会拒绝该路径以防止环路  

#### 3.4.5. Populating Forwarding Table（填充转发表）

路由器并不直接使用 BGP 路径进行转发  
而是需要结合 **域内路由协议（IGP，如 OSPF）** 来确定本地输出接口  

组合逻辑：路由器（如 AS1 里的 1d）通过 iBGP 得知到达外部前缀 X 的最佳出口是网关 1c。接着，它查询本地 IGP 表，得知到达 1c 的最短内部路径需要走接口 $l_1$  

结果：路由器最终在转发表中插入一条规则：目的地前缀 X → 输出接口 $l_1$  

#### 3.4.6. Hot Potato Routing（热土豆路由）

一种基于“自私”原则的域内路径选择算法

核心理念：  
一个AS内部router（如2d）发现有多个gateways（如2a和2c）都可以到达同一个目的地X时  
选择 **内部开销最小** （IGP代价最低）的那个  
*也就是说“自私”指内部路由对网关的选择会偏向于让自己“方便”*  

特点：  
这种策略只关心尽快将分组“扔出”本自治系统，而不在乎该网关在系统外的 AS 跳数是否更多  

#### 3.4.7. BGP Route Selection（BGP路由选择）

router可能了解有多条route到达同一目的地  
选择route的依据：（按优先级排序）  

1. **Policy Decision**  
    本地偏好值属性  
2. **Shortest AS-PATH**  
    最短AS路径优先  
3. **closest NEXT-HOP router**  
    也就是hot potato routing  
4， additional criteria（额外标准）  
    如最低的路由器ID等  

## 4. SDN Control Plane（软件定义网络控制平面）

在网络层控制平面中  
**软件定义网络（SDN）** 代表了从传统“每路由器控制”向“逻辑集中式控制”的重大转变  
通过将控制逻辑与转发硬件解耦，实现了网络流量的灵活编程控制  

### 4.1. 四大核心特征

1. **基于Flow的转发模型**  
    传统路由器基于目的地址进行分组转发  
    SDN交换机基于“流（Flow）”进行转发  
    流是具有共同特征（如源/目的IP、端口号、协议类型等）的一组分组的集合
2. **控制与数据平面分离**  
    转发设备仅负责匹配动作  
    复杂的逻辑（Flow Table的计算和下发）由远程控制器完成  
3. **外部控制功能**  
    控制逻辑实现在数据平面交换机之外的远程控制器上  
4. **可编程控制应用**  
    通过在上层运行应用程序（例如routing、firewall、load balancer等）  
    来定义网络行为  

### 4.2. SDN体系结构

三层架构：  

1. **网络控制应用层（Application Layer）**  
    网络的“大脑”。实现路由选择、访问控制、流量工程等逻辑。  
    它们通过北向 API 与控制器交互  
2. **SDN控制器层（网络操作系统，NOS）**  
    核心中枢。负责维护全局网络状态信息（如链路、交换机、主机状态的 Network Map），并协调上层应用与底层硬件  
    通过南向 API 与数据平面交换机交互  
3. **数据平面交换机层（Data Plane）**  
    Data-Plane Switches  
    简单、快速的通用交换机（如白盒交换机）。根据控制器安装在流表中的规则执行转发

### 4.3. SDN Controller  

SDN 控制器被视为网络操作系统 (Network OS)  
其功能类似于计算机操作系统  
通过提供高层抽象来简化网络控制逻辑的实现

主要组件：

1. 通信层：与受控设备交互（南向接口）  
    控制器最底层的组件，负责控制器与底层网络交换机之间的通信  
    - 功能：下发Flow Table，收集网络状态信息  
    - 协议：典型协议为OpenFlow，也支持SNMP等协议  
2. 网络范围状态管理层  
    控制器的核心，维护着整个网络的全局视图  
    - 本质：一个分布式数据库，存储包括LS、交换机信息、主机信息以及流表统计数据  
    - 逻辑集中：NOS 承担了收集全网状态的任务（这原本是传统分布式路由算法中最困难的部分），从而构建出**全局网络地图 (Network Map)**  
3. 应用层接口（北向接口）  
    通过 API 向顶层的网络控制应用（如路由选择、负载均衡、访问控制）提供抽象  
    - 抽象机制：允许App开发者在抽象的”网络图“上实现逻辑，无序关注底层细节（类似OS功能）
    - 接口形式：通常采用RESTful API，允许App表达网络”意图“  

### 4.4. OpenFlow Protocol

运行在Switches和SDN Controller之间（即属于南向接口）的通信协议  
*（他们通过TCP连接进行通信）*  

**控制器到交换机 (Controller-to-Switch)**  
features（查询交换机功能）  
configure（查询或设置交换机参数）  
modify-state（用于添加或删除流表项）  
packet-out（命令交换机从特定端口发出分组）  

**异步消息 (Asynchronous)**  
由交换机发起  
packet-in（将无法匹配或需要处理的分组传给控制器）  
flow-removed（通知控制器流表项被删除）  
port-status（通知控制器端口状态变化）  

### 4.5. 运行实例分析

1. 故障通告：当交换机 S1 检测到链路故障时，通过南向接口向控制器发送 OpenFlow port-status 消息。
2. 状态更新：SDN 控制器接收该异步消息，并在其网络范围状态管理层（存储链路、交换机、主机等信息的分布式数据库）中更新链路状态。
3. 触发应用：控制器调用已注册过状态变更事件的网络控制应用，例如 Dijkstra 链路状态路由应用。
4. 计算路径：路由应用通过北向接口访问控制器的全网拓扑视图（Network Map），在全局视图上重新计算避开故障点的最优路径。
5. 生成规则：路由应用与控制器的流表计算组件交互，根据新路径生成对应的流表条目。
6. 下发流表：控制器利用 OpenFlow 协议（如 modify-state 消息）将新流表安装到需要更新的交换机中，从而实现对底层数据平面前转行为的精确控制。

解析总结： 与传统路由器独立运行算法不同，SDN 通过控制器收集全局信息并集中决策，使得网络管理更加灵活且易于编程控制。  

### 4.6. SDN面临的挑战

**控制平面的强韧化 (Hardening)**：  
控制平面必须作为一个可靠、安全、高性能且可扩展的分布式系统来构建，以避免单点故障

**安全与可靠性**：  
需要解决故障恢复能力（Robustness），并思考如何从设计之初就将安全性和确定性“内置”到系统中  

**满足特定任务需求**：  
如何让 SDN 满足实时性要求极高、超高可靠或超高安全的特定任务场景。

**大规模扩展性**：  
虽然 SDN 在数据中心表现优异，但将其扩展到全球互联网规模（跨越多个自治系统 AS）仍是一大挑战。  

**5G 网络集成**：  
SDN 是 5G 蜂窝网络架构的关键，需处理其固有的复杂性和虚拟化功能需求  

## 5. ICMP

ICMP（Internet Control Message Protocol，互联网控制报文协议）  
控制平面的重要组成部分，主要用于主机和路由器之间沟通网络层的信息  

### 基本职能

**补偿机制（Compensation Mechanism）**：  
IP 协议虽然提供“尽力而为”的服务  
但遇到丢包或错误时会保持“沉默”  
ICMP 作为 IP 的伴随协议  
负责在路由器或主机处理 IP 数据报出现问题时发送差错报告。  

**主要用途**  

- 差错报告（Error Reporting）  
    如目的地不可达、TTL 超时、IP 首部损坏等
- 网络诊断（Network Diagnostics）  
    通过回显请求（Echo Request）和应答（Echo Reply）测试节点是否存活  
- 路由控制（Routing Control）  
    例如 ICMP 重定向（Redirect），路由器通知主机有更优的路径到达特定目的地  

### ICMP Message Format And Encapsulation

**封装位置**  
ICMP保存逻辑上位于IP协议之上  
但实际上是作为IP Datagram的Payload进行封装和传输  

#### 核心字段

**Type**  
类型：标识报文大类（如差错报告、回显请求等）  

**Code**  
代码：在类型下细分具体错误原因  

**错误相关数据**  
通常包含引起错误的 IP 数据报的首部以及其数据部分的前 8 个字节  
以便源端识别是哪个协议（如 TCP/UDP 端口）导致的错误  

### 常见ICMP报文类型

| Type | Code | Description                 | 应用场景            |
| ---- | ---- | --------------------------- | ------------------- |
| 0    | 0    | 回显应答 (Echo Reply)       | Ping 成功响应       |
| 8    | 0    | 回显请求 (Echo Request)     | Ping 发起测试       |
| 3    | 3    | 目的地端口不可达            | Traceroute 结束标志 |
| 11   | 0    | TTL 超时 (TTL Expired)      | Traceroute 探测路径 |
| 12   | 0    | IP 首部损坏 (Bad IP Header) | 数据报格式错误      |

经典应用：  

- Ping：利用 ICMP 回显请求（Type 8）和应答（Type 0）来测量源到目的地的 RTT（往返时延）并判断可达性。

- Traceroute：
    1. 源端发送 TTL 逐渐递增（1, 2, 3...）的 UDP 分组。
    2. 路径上的第 n 个路由器将 TTL 减至 0，随后丢弃分组并回发一个 ICMP 类型 11（超时） 报文，从而暴露自身 IP 地址。
    3. 当分组最终到达目的主机时，由于源端使用了不常用的端口号，主机会回发 ICMP 类型 3, 代码 3（端口不可达） 报文，探测随之停止。
