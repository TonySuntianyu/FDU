## 一、最短路径算法总结

### 1. Dijkstra算法
- **核心思想**：贪心策略，每次选择距离起点最近的未访问顶点，逐步扩展最短路径树
- **适用场景**：非负权重的有向图或无向图，单源最短路径问题
- **时间复杂度**：O(V²)（使用邻接矩阵）或 O((V+E)logV)（使用优先队列+邻接表）
- **空间复杂度**：O(V)（存储距离和前驱信息）

### 2. Floyd-Warshall算法
- **核心思想**：动态规划，通过中间顶点逐步更新所有顶点对之间的最短距离
- **适用场景**：所有顶点对之间的最短路径，稠密图
- **时间复杂度**：O(V³)
- **空间复杂度**：O(V²)

### 3. Bellman-Ford算法
- **核心思想**：动态规划，对所有边进行V-1轮松弛操作
- **适用场景**：可以处理负权边，检测负权环
- **时间复杂度**：O(VE)
- **空间复杂度**：O(V)

### 几种算法的对比
| 算法名称       | 核心思想                                                                 | 适用场景                                   | 时间复杂度                  | 空间复杂度                  |
|----------------|--------------------------------------------------------------------------|--------------------------------------------|-----------------------------|-----------------------------|
| Dijkstra算法   | 基于贪心策略，每次选择当前距离起点最近的未访问节点，更新其邻接节点的距离，直至遍历所有节点 | 带非负权边的图、单源最短路径（如静态导航） | 邻接矩阵：O(n²)；邻接表+优先队列：O((n+e)logn)（n为节点数，e为边数） | 邻接矩阵：O(n²)；邻接表：O(n+e) |
| Floyd-Warshall算法 | 基于动态规划，通过中间节点k松弛任意两点(i,j)的距离，逐步更新全局最短路径   | 多源最短路径、稠密图、允许负权边（无负环） | O(n³)                       | O(n²)                       |
| Bellman-Ford算法  | 迭代松弛所有边，最多迭代n-1次，可检测负权环                               | 带负权边的图、单源最短路径、需检测负权环   | O(ne)                       | O(n)                        |

## 三、稀疏图 vs 稠密图的表示方法比较

### 稀疏图（E << V²）
- **邻接表表示**：
  - 空间复杂度：O(V + E)
  - 遍历邻接点：O(度(v))
  - **优势**：空间效率高，适合边数少的图
- **邻接矩阵表示**：
  - 空间复杂度：O(V²)
  - 遍历邻接点：O(V)
  - **劣势**：浪费大量空间存储不存在的边

### 稠密图（E ≈ V²）
- **邻接表表示**：
  - 空间复杂度：O(V + E) ≈ O(V²)
  - 遍历邻接点：O(V)
  - **劣势**：指针开销，缓存不友好
- **邻接矩阵表示**：
  - 空间复杂度：O(V²)
  - 遍历邻接点：O(V)
  - **优势**：访问速度快，缓存友好，实现简单

### 本题场景的选择

**选择：邻接表表示**

**原因**：
1. **实际道路网络通常是稀疏图**：自动驾驶导航的地图符合稀疏图特征，节点为路口/地点，边为道路，实际中道路数量远小于节点数的平方（不会每个地点都直接连通）。
2. **空间效率**：邻接表只存储实际存在的边，在处理大规模地图时存储效率更高，可节省内存
3. **算法匹配**：Dijkstra算法使用优先队列时，需要遍历每个顶点的邻接边，邻接表的时间复杂度O(E log V)优于邻接矩阵的O(V² log V)
4. **动态更新友好**：添加或删除边在邻接表中操作更简单

## 四、Dijkstra算法的回溯机制

### 回溯机制原理

Dijkstra算法通过维护一个**前驱表（predecessor table）**来实现路径回溯：

1. **前驱节点数组**：定义数组`prev[]`，`prev[v]`表示从起点s到v的最短路径中，v的前一个节点。
2. **初始化**：`prev[s] = -1`（起点无前驱），其他节点`prev[v] = -1`或默认值。
3. **更新机制**：当通过节点u松弛节点v的距离（`dist[v] > dist[u] + w(u,v)`）时，更新`dist[v]`的同时，设置`prev[v] = u`。
4. **回溯过程**：从终点t开始，通过`prev[t]`找到前一个节点，依次递归追溯至起点s，将路径节点反转后即为s到t的最短路径。
   - 示例：终点t的回溯链为t → prev[t] → ... → s，反转后得到s → ... → prev[t] → t。


### 具体实现步骤

```
1. 从终点end开始
2. 将end加入路径
3. 查找prev[end]，得到前一个顶点
4. 重复步骤2-3，直到到达起点start
5. 将路径反转，得到从起点到终点的正确顺序
```

### 示例

假设找到的最短路径是：A → B → C → D

- prev[D] = C
- prev[C] = B  
- prev[B] = A
- prev[A] = null（起点）

回溯过程：
1. 从D开始：path = [D]
2. prev[D] = C：path = [D, C]
3. prev[C] = B：path = [D, C, B]
4. prev[B] = A：path = [D, C, B, A]
5. 反转：path = [A, B, C, D]

### 可能遇到的困难或挑战

1. **CSV格式多样性**：不同测试用例的CSV格式可能略有差异（有无道路类型字段）
   - **解决方案**：在FileParser中检测字段数量，动态调整解析逻辑

2. **双向道路处理**：需要将一条双向道路转换为两条有向边
   - **解决方案**：在解析时根据"道路方向"字段判断，双向道路添加两条边

3. **大规模地图性能**：顶点和边数量很大时，算法可能较慢
   - **解决方案**：使用优先队列优化Dijkstra算法，未来可考虑A*算法

4. **路径不存在情况**：起点和终点可能不连通
   - **解决方案**：在Dijkstra算法中检测，如果终点距离仍为无穷大，返回未找到

5. **浮点数精度**：权重计算涉及浮点数，可能存在精度问题
   - **解决方案**：使用double类型，在比较时使用epsilon避免精度误差
